保持以下行为：project模式自动读取，strict模式逐次确认；文件工具保留名、符号链接、硬链接和边界规则；read的UTF-8/大小/分页/version；glob/grep的模式、排除、排序和上限；write/edit的版本及原子提交；bash逐次确认和进程清理；默认一次40+10复核、50次总请求和既有模型。工具参数不新增由模型填写的“可信身份”字段，不增加依赖。

### 2.2 身份与内容是两个不同的检查

**身份绑定**是宿主在准备读取提案时保存的不可变记录。它回答“这还是我刚校验的那个对象和路径链吗”。dev表示设备号，ino表示文件系统对象编号；mode包含对象类型和权限位，nlink表示硬链接数量。这些值用于本地检查，不把inode当成全球唯一或永久身份。

**内容版本**是read成功取得稳定内容后签发给edit的version。它回答“编辑所依据的完整内容是否仍有效”。不得用内容哈希代替身份绑定；同内容的新文件仍是另一个对象。也不得把读取授权改成编辑版本检查，导致普通内容更新一律被拒绝。

| 对象或变化 | 推荐判定 |
|---|---|
| 根与每一级父目录 | 比较规范化路径链及dev/ino/mode；同一路径被另一个普通目录替换、类型或权限变化均失效 |
| 明确请求的普通文件 | 比较dev/ino/mode/nlink，且维持nlink必须为1的既有规则；同字节替换也拒绝 |
| 明确请求的目录 | 比较dev/ino/mode。不能用目录mtime/ctime、大小或nlink作为相同对象的必要条件；正常增删子项可能改变它们 |
| 同一文件对象在批准前原地更新内容 | 身份未变且仍合法时允许读取执行时的内容；读取期间的一致性检查仍适用。新内容的read version才可用于edit |
| 编辑器通过临时文件rename替换文件 | 即使用户认为是一次普通保存，也属于身份变化：旧调用拒绝，重新提出调用并取得新授权 |
| 搜索目录内正常新增文件或子目录 | 不自动使目录授权失效。扫描仍可观察执行时的合法内容；不保证新增项必定被并发扫描看到 |
| glob/grep的path明确指向文件 | 与read采用同样的文件身份规则，不能只修目录型搜索 |
| 原目标消失、变成链接/特殊文件/非法多硬链接 | 不读取；保留明确的路径变化或既有禁止原因，不借strict批准放行 |

搜索只冻结明确请求的范围及其父路径链，不在批准前枚举和冻结整个目录树。遍历到的后代继续走逐路径校验与普通文件快照检查。不能因此放松已观察到的候选文件/父路径变化检查；也不能要求所有尚未访问的后代与批准时完全相同。测试分别证明“搜索范围被换掉必须拒绝”和“范围没换、正常增加子项仍可搜索”。

启动cwd仍按原设计只解析一次，之后核对根身份。若会话根被替换，本会话不能通过重新prepare自动改认新根，须重新启动。普通目标或父目录改变后，根保持有效时，可以用新的调用重新校验和确认。

### 2.3 生命周期与错误结果

实现应满足以下顺序，具体内部类型名可在实现时确定：

1. **prepare**：完成既有路径规则校验；把根、父链及目标的原始身份复制为私有不可变值。绑定到当前PreparedTool、工具参数和调用，不接收模型提交的绑定值。
2. **授权**：strict等待当前用户决定；project产生原有自动授权事件。两种模式使用同一身份保护，不能只在strict补丁中保护。
3. **execute入口**：先处理取消和一次性执行状态，再复核原绑定。每个提案只执行一次；失败、完成或已取消后不允许借同一提案再执行。拒绝的提案直接弃用。
4. **实际I/O**：把原绑定传给read/snapshot/search，不在底层重新捕获并替换原绑定。读取在open前及fstat后核对实际对象；扫描在异步等待返回后、继续枚举/读取前核对已授权范围。文件句柄和目录句柄在成功、拒绝、错误、取消时均释放。
5. **返回前**：再次核对原绑定，随后才公开内容、文件名或可编辑version。身份失效时丢弃本次已缓冲结果；不向终端、tool_result、后续API或普通内容日志输出替代对象的数据。

扫描内的通用catch不能把“授权范围身份失效”降级为普通`skipped`后继续扫描或返回completed。必须区分整个范围失效与单个未被授权固定的候选文件无权限等普通跳过。可以使用内部错误类型区分，外部错误分类保持清晰。

普通目标/父链身份不匹配使用`path_changed`：`is_error=true`、`status=failed`、`modified=false`，不带结果数组、文件正文或version。对象消失可保留`ENOENT`，无法完成复核时可保留`EACCES`等实际I/O原因但仍不得读取；已知链接/特殊文件等可保留既有明确错误码。取消仍用既有取消分类，不能改称身份变化；读取过程中内容不稳定仍按原`file_changed`等规则报告。

失败后不能自动重签新绑定并沿用原y，也不能自动回退bash。模型以后可以提出新调用；strict必须出现新的确认，project必须生成新的自动决定。普通身份拒绝不要求永久终止任务；用户取消和日志故障的停止规则保持。任何同批后续调用仍受其独立授权约束。

Trace用同一toolUseId关联准备、授权、身份核验与结果。准备身份摘要须在授权前记录；核验事件记录绑定摘要、阶段及通过/失效原因。摘要由宿主生成，不进入模型可伪造的输入。不得把替代文件内容或认证头加入错误日志。日志故障沿用既有停止规则，不为新增日志放宽E-01/E-02。

### 2.4 支持边界

这是应用层的身份复核，不是操作系统沙箱，也不是文件系统事务。对可观察的普通文件/目录替换、权限变化、支持的本地文件系统及受控异步时点作保证。不能声称消除了所有检查与使用之间的外部竞争、inode复用或“在两次检查间换回原物”的不可观察变化。

测试屏障用来指定已发生替换的时点。通过这些测试不能外推为任意并发写入下的整棵目录一致性。既有read内容一致性检查、文件大小和扫描资源上限继续独立成立。
