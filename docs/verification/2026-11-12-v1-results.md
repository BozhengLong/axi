## 1. 已交付的产品

read、glob、grep、write、edit 已与 bash 接入同一工具分派。默认 project 自动读取普通项目文件；strict 仍逐次确认。修改展示完整差异，使用读取版本与唯一匹配，确认后再次检查；write 不覆盖已有目标。Ctrl+C 保留已完成修改，补齐未执行调用的结果，遇到未知提交状态或关键日志失败时停止。原生日志记录自动/人工授权、提案和实际提交状态。

产品门槛：macOS 类型检查及 89 项测试、582 个断言；Linux 类型检查及 87 项测试、571 个断言；六个产品错误变体；真实终端/模拟 API 场景均通过。两项主机适配器测试在 Linux 检查点之后加入，不能把本机 89 项写成 Linux 89 项。后续设施修复的本机测试结果单列在第 4 节。

文件工具不是操作系统沙箱。最终版本检查与替换之间仍存在外部竞争窗口。正常 Ctrl+C 的保证不等于崩溃恢复，原有同进程组清理也不保证终止主动脱离进程组的进程。

## 3. 两次停止及证据

### 首次：公开命令与独立验收不一致

公开环境提供的 AVA 命令没有限定原测试路径。新增 node:test 文件后，AVA 也会收集这些文件，然后报告 No tests found 并退出 1。独立验收一直显式指定 `test.js` 或 `test/index.js`，因此此前 14 项校准和 8 次流水线模拟没有覆盖这个缺口。

用两道参考实现离线原样执行公开命令，均复现退出 1；显式指定原测试范围均退出 0。可选 XO 的入口也写错，包本身已安装。修订仅改变公开环境命令，没有改产品、题目行为、参考或判定规则。两道参考各新增 4 项公开命令/入口校准全部通过，14 项校准和 8 次流水线模拟重新通过。

停止决定在当前新 Axi 成绩可见前作出。等它交付且原验收写入后，才停止控制器。首批 4 个模型运行均正常结束；第四份结果汇合到 stopped-results.json，原 results.json 未覆盖。首组三方未跑到 Claude；两份已启动样本一并排除，不能只保留旧 Axi 的成功样本。

首批新 Axi 的类型检查原退出 137、无诊断文本。同一产物、同一命令在独立副本复验，436 毫秒退出 0。原退出原因未确定；原机判仍保留失败，不能用复验通过覆盖当时记录。

### 第二次：连接异常触发观察器提前终止

修订批次新 Axi 的第 18 请求于北京时间 02:29:29 发出，02:33:43 出现上游连接异常。转发器返回 502 并记录 `upstream_connection`。终端显示 Axi 准备在 1 秒后进行第 1/3 次重试，但控制器看到 `faults` 非空就发送 Ctrl+C。

[当时的新适配器](https://github.com/BozhengLong/axi/blob/fecf492/scripts/eval/v1/adapter.ts)、[旧适配器](https://github.com/BozhengLong/axi/blob/fecf492/scripts/eval/adapters.ts)和[转发器](https://github.com/BozhengLong/axi/blob/fecf492/scripts/eval/container/relay.ts)的正式源码快照证明：当时的两个 Axi 观察器都会因历史连接错误立即结束，Claude 的观察路径不同。这是评测设施对产品重试的干预，不能归因于 v1 文件工具。为何上游连接关闭，现有证据不能确定。

原运行状态为 runner_error，依据请求证据分类为 environment_indeterminate。独立机判只有 DELIVERY 组失败；功能/类型/保护和回归都通过。但没有最终交付说明，所以报告真实性不可审查，完整交付仍未完成。

唯一一次恢复额度已用于首次设施修复后的整组重做。第二次事件触发后，按 D7 停止新增运行。原截止仍为北京时间 19:55:22，没有延长，也没有建立第三个真实模型批次。

## 4. 停止后的离线设施修复

产品 src 保持不变。设施修复将历史 upstream_connection 与致命故障分开：连接错误完整留证，产品自行决定是否重试；预算、证据上限、模型不符、权限配对失败和未知故障仍立即停止。已恢复的历史连接错误也不再永久阻断下一轮。

命令执行记录增加 timedOut 和 durationMs。普通退出 137 与被本机超时器终止可明确区分；这个字段无法事后补回首批的缺口。修复后的本机类型检查及 91 项测试、595 个断言通过。专用 7 项传输模拟全部通过：三种 CLI 首次连接错误后均恢复，两个 Axi 均在连续四次错误后自然结束，两个 Axi 的请求预算仍硬停止。原有 9 项交互模拟也通过，16 份模拟 Trace 收齐，132 份清单文件哈希一致。新镜像的17份新产品源码和11份旧产品源码逐文件一致，没有混入测试镜像层。修复提交为 `4077146`；新验证镜像为 `sha256:5d82c0e27b4d9eeab57ab7b000f03526e1326685ba6f272cf9ed00d244ee6007`。

该修复没有用于前述 6 次正式运行。新镜像与模拟证据单列，不替换原镜像 `sha256:89533abd22cabe73692800a8b7a48ea0849edc6fddd8435cd85898d7938f21cf`、原源码快照或原机判。新真实模型轮次须按[补全方案](../08-v1-evaluation-completion-plan.md)重新确认预算并冻结。

## 6. 当前结论与下一步

v1 的工具、权限和中断机制已有实际验证，C7 已知能力没有在这两次回归中退化。固定流程证明 project 读取不需要逐次确认；本批没有足够的完整三方样本，不能声称整个任务确认次数、成功率或速度更好。
