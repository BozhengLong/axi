## 决策与代码范围

用户确认“取消任务次数上限，连续故障仍有等待上限（推荐）”。依据[设计21/D1–D2](../21-unbounded-task-execution.md)，先提交设计`c2c63d8`，再在`codex/v1-unbounded-tasks`实现。该分支从C2 `dbe7e145d205c21b580d8c2ee2dcf58c408380d8`派生。旧C2及已关闭INCOMPLETE的正式批次保持，不补跑、不回填分数。

取消40次工作、10次复核、50次总请求，以及Agent外层默认50次循环限制。auto在有修改或获准bash的正常初稿后进入一次复核；off不添加复核。两种模式均不设任务请求总数上限。

连续临时错误改用每次逻辑模型调用独立的恢复窗口，默认10分钟，环境变量`AXI_RETRY_WINDOW_MS`可配置。单次HTTP仍最多5分钟，并受窗口剩余时间约束。成功后下次调用重新计时；重试不重复已执行工具。窗口到期的任务终态为`retry_exhausted`，明确未完成，保留文件与Trace。

Trace升为版本4，记录调用ID、尝试数、工作/复核计数、恢复窗口、退避安排及结束原因。`budget`字段保留名称，`unlimited=true`、`remaining=null`。旧读取器不能继续假设40/10配额。

逐字节核对确认：工具实现及schema、权限模块、系统提示、依赖/锁文件与C2相同。复核提示只移除次数配额及相关停止措辞；未加入新的任务完成策略。源文件哈希和逐项记录见[验证数据](2026-11-17-unbounded-task-development.json)。

环境为macOS、Bun 1.3.14。`bun install --frozen-lockfile`成功，锁文件未变。全部新验证只使用本地模拟API、临时文件及受控时钟，真实模型调用为0。

真实CLI四条轨迹分别验证：

1. 默认复核、off、复核审批和拒绝理由。3项任务、10次请求，拒绝的命令没有执行。
2. 复核退避期间Ctrl+C。共4次请求，第一项任务为interrupted，已写文件保留；下一项任务正常完成。
3. 长任务。共76次请求、75次完整响应；第40次返回SSE限流错误，下一次请求体相同。工作62次、复核14次，只进入一次复核。只提交一次文件写入，其余72次是读取。
4. 恢复窗口设为120毫秒。首个写入保留，后续限流后等待到期，任务为retry_exhausted；下一项任务正常完成。共3次请求，没有重做写入。

上述SSE限流与HTTP 429分别验证，不能把HTTP状态200的流内错误误写为HTTP 429。每条CLI均保存请求体、原始响应文本、stdout/stderr、原生日志和生成文件。服务端收到的93次请求与原生request数一致；工具调用ID没有重复。

## 发现与修正

早期针对性测试为52通过、1失败：断言要求中文取消文案，而原生AbortError使用英文消息。改为检查错误类型，没有改变取消行为。完整208项测试随后通过。

第一次最终类型检查发现新测试的fake fetch缺少Bun类型声明中的`preconnect`属性。已修正测试类型转换，并把工具不重放断言改为核对唯一工具调用ID。最终类型检查和20项针对性复验通过。这两项改动仅涉及测试；完整套件验证后的产品源码未再改变，因此未无因重复完整套件。失败输出仍保留，不用通过记录覆盖。
