## 环境问题与修复证据

- node-csv的Nx在没有nx.json的Lerna项目内默认写node_modules缓存，和只读依赖冲突。依据固定版本源码，缓存改为各容器独立`/tmp/nx-cache`及`/tmp/nx-workspace`，并关闭该隔离环境中的Nx daemon。未改变用户主机配置、依赖版本或镜像。
- 原并行根测试在2CPU/4GiB/256进程或线程的固定资源中失败。诊断观察到`pids.events`的max由0增为2，OOM计数为0。两份诊断测试只转发子进程stderr，没有用于资格。原态及两参考改用未修改测试的串行workspace命令后通过，根测试的pids max保持0。
- 公开命令现为`npm run build -- --concurrency=1`及`npm test -- --concurrency=1`。所有workspace仍执行，资源上限保持，不以跳过demo或增加资源取得通过。5次资格均采用同一配置。
- 首次挂载嵌套只读依赖时，Docker先创建了包目录，迟复制源码会遗漏文件。旧`find -exec cp`还不能可靠传递单个cp失败。现在先把完整输入复制到独立任务卷，再挂依赖，并核对实际cp退出码。旧缺文件和EROFS结果保留，未算代码或模型失败。
