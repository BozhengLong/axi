## 为什么需要看响应流

第 1 次请求建立了 HTTP 流，但流内没有 `message_start` 或 `message_stop`。错误事件在 10:28:41.703 报告上游 401。在同账号、同冻结模型、同部署的查询窗口内，网关有一条开始时间精确到同一毫秒的记录，标为 `success`，总 token 为 0。该行没有返回可与上游错误直接匹配的请求 ID，关联依据是时间、模型和部署。后 4 次通过消息 ID 精确匹配到同一部署的 4 条成功记录。

此前的 94 条记录均被网关标为成功，且各自的总 token 均大于 0。前次排查已用封存 Trace 验证其中 5 次完整响应。94 条记录无法证明每一份响应流都正常结束，也无法推断具体凭据的状态。[前次归因](2026-11-19-r6b-oauth-attribution.md)
