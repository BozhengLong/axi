## 2. 发现的问题：P02-IDENTITY-01

既有[设计07 §4.2](../07-v1-design.md#42-路径与搜索范围)要求：根目录、父目录或目标在等待确认期间发生身份变化时，放弃原提案。[P-02矩阵](../../evals/specs/v1-tools-v1/acceptance-matrix.md)要求已观察到的身份变化使提案失效。该要求在本轮之前已经公开，不是看到结果后新增的标准。

真实CLI复现步骤：

1. 启动冻结C，用户切换到`strict`，模型模拟回复提出读取或搜索。
2. 等待真实PTY出现“执行这次读取？[y/N]”。此时产品已校验目标路径。
3. 控制器用真实`rename`把原普通文件/目录移到旁边，再在原路径创建另一个普通目标。记录前后inode、字节、模式及Git。这个替换在输入y之前完成，不依赖随机延时。
4. 输入一次`y`。按契约应拒绝旧提案。实际返回`completed/code=ok`，并把替换后的内容或文件名送入下一次本地API请求。

受影响路径：read目标替换、read父目录替换、glob搜索目录替换、grep搜索目录替换。每个场景在两平台各连续运行预定5次，**40/40次违反该条款**。正常读取/搜索、替换后明确拒绝、目标被换成symlink的对照，共70/70次符合预期。驱动没有超时、导入错误或异常退出。

根因在[候选registry.ts](https://github.com/BozhengLong/axi/blob/0f4a2c4df87b01d6290ff81dfea2541a5169e2ae/src/tools/registry.ts#L34-L45)：prepare校验路径，但read/glob/grep的执行闭包只保存路径参数，没有保存并复核批准前目标和父目录的身份。执行时重新校验的是新目标；新目标仍是项目内普通文件，所以被接受。根身份检查、symlink拒绝和write/edit提案版本复核不能覆盖这个缺口。

按冻结契约，这是一个未解决的授权身份边界缺陷，归入H1并阻断G1/G2。一个根因不因工具数、重复数和平台数而重复计数。所有数据都是测试夹具；本轮没有真实秘密泄露、工作区外读取或文件/Git损坏。问题是读取了旧提案未绑定的新目标。没有真实模型任务，不产生Claude能力结论。
