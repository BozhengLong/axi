## 5. 新发现的Emittery缺陷

本次实现对溢出的项直接执行`queue.shift()`、忽略新项或清空队列。`anyEvent()`内部为事件生成`Promise.all([eventName, eventData])`。即使调用者已经处理输入Promise的拒绝，这个新生成的内部Promise仍需由库负责。

当内部Promise被溢出策略丢弃，调用者已经无法再通过`next()`消费它。该产物没有处理它的拒绝，固定Node22默认行为会使整个进程退出。前两次普通监听调用仍然发生，但之后的进程级失败已经超出单个迭代器的错误边界。

这违背公开契约中的溢出隔离要求。报告把未处理拒绝笼统列为“原有行为，未改”，不足以排除新溢出路径引入的回退。这里区分两点：其执行命令/结果准确；把当前风险全部归到旧行为的判断不成立。尚无证据表明这是Axi文件工具的缺陷。

### 独立复现与反例

[最小复现程序](2026-11-14-v1-rc-promise-probe.mjs)使用已经自行处理拒绝的输入Promise，在事件循环结束前调用两次`next()`并处理结果，然后关闭迭代器。将程序复制到待测Emittery产物根目录，在固定Node22镜像中分别运行：

```sh
node promise-probe.mjs drop-oldest
node promise-probe.mjs drop-newest
node promise-probe.mjs error
```

先做带全局观察器的诊断，再移除观察器验证默认进程行为。两种诊断分别对原库、参考实现、当前产物和全部6份历史Emittery产物运行，每种27次，共54次离线运行。

| 产物 | 三种策略的全局未处理拒绝 | 三种策略的默认进程退出码 |
|---|---|---|
| 原上游库 | 均为0 | 均为0 |
| 参考实现 | 均为0 | 均为0 |
| 本次新Axi开发产物 | 每种1次 | 均为1 |
| 历史B第1轮三方产物 | 均为0 | 均为0 |
| 历史B第2轮三方产物 | 每份每种1次 | 均为1 |

所有运行均正常结束或按Node默认错误行为退出，没有外层超时。这是**事后补充诊断**，不是静默修改冻结评分器。旧轮的原始成绩及当时结论保留，新证据在此单列；不能继续把旧结论外推到这个新增边界。第1轮新Axi在本诊断通过，也不撤销它此前已证实的`then` getter缺陷。

原库没有有界缓存，仍可消费两条事件，因此同一程序没有内部拒绝遗失。参考实现处理内部Promise拒绝，也正常结束。这个对照说明本次失败不只是调用方忘记处理输入Promise。
