## 已复现的问题

### R1：提前输入可残留到确认提示，优先级 P1

- 位置：[src/ui/terminal.ts](../../src/ui/terminal.ts)，第 45–46 行；[src/ui/permission.ts](../../src/ui/permission.ts)，第 10–13 行。
- 预期：等待模型时键入的内容应被丢弃。在新的命令确认提示下直接回车，应拒绝命令。依据是 v0/D3 和入口帮助文本。
- 原因：`Terminal.read()` 用 Ctrl+U 清理输入。该操作只删除光标之前的内容。光标之后的内容仍在 readline 的输入缓冲区中。
- 复现方法：用 Python `pty.fork()` 建立伪终端，设置 `TERM=xterm-256color`，运行真实 `Terminal` 和 `confirmCommand`。在确认提示出现前写入 `y` 和 Ctrl+A，使光标移到行首；提示出现后只写入回车。
- 实际结果：`confirmCommand` 返回 `{"allowed":true}`。对照组提前输入 `y`，但不移动光标，提示后直接回车得到 `{"allowed":false}`。
- 验证边界：只验证授权返回值，没有执行待确认的命令。不是所有回车都会批准；必须满足上述残留输入条件。
- 影响：提前输入可能被当成本次授权，违背逐次确认规则。
- 修复建议：在新提示与中断时清除整行输入，覆盖光标两侧。增加伪终端回归测试。现有 CLI 测试使用管道，未覆盖终端光标移动。
- 状态：已复现，未修复。

### R2：Bun 1.3.14 的连接拒绝错误不触发重试，优先级 P2

- 位置：[src/api/client.ts](../../src/api/client.ts)，第 42–45 行和第 111 行。
- 预期：按 v0 错误处理设计，网络临时错误最多重试 3 次。
- 原因：普通网络错误只有属于 `TypeError` 时才进入重试。本机运行时返回的连接拒绝错误属于 `Error`。
- 复现方法：创建本地 HTTP 服务取得临时端口，再关闭服务；移除测试子进程的代理变量，向该端口调用真实 `fetch`，并通过 `APIClient.call()` 重复检查。使用假 key，不访问外部 API。
- 实际结果：Bun 版本为 `1.3.14`。错误的 `constructor` 和 `name` 均为 `Error`，`code` 为 `ConnectionRefused`，`instanceof TypeError` 为 `false`。客户端只发出 1 次请求，没有重试。
- 来源核对：查阅时的 [Bun fetch 文档](https://bun.sh/docs/runtime/networking/fetch#error-handling) 将连接错误描述为 `TypeError`。该页面面向较新的运行时，不能代替本机版本实测。本结论限于已复现的 Bun 1.3.14 行为。
- 修复建议：为支持的 Bun 版本识别明确的网络错误类型或错误码，保留用户中断不重试的规则。补充真实本地连接失败测试，不能仅依赖人工构造的异常。
- 状态：已复现，未修复。未验证所有网络错误类型或其他 Bun 版本。

### R3：跨仓库运行时，日志不会自动排除于 Git，优先级 P2

- 位置：[src/log.ts](../../src/log.ts)，第 9–18 行；[README](../../README.md)，第 20–26 行和第 56 行。
- 触发条件：按 README 在另一个 Git 仓库中启动 Axi，且目标仓库没有忽略 `.axi/`。
- 原因：日志写入启动工作目录。Axi 自身的 `.gitignore` 不会作用于另一个仓库。`SessionLog` 没有为目标目录建立排除规则。
- 复现方法：创建临时 Git 仓库，用 `SessionLog` 写入一条虚构请求并关闭日志，然后运行 `git status --short --untracked-files=all`。
- 实际结果：输出 `?? .axi/logs/<session>.jsonl`。日志可被普通 Git 添加操作收录。测试结束后已删除临时目录。
- 影响：日志可能包含任务文本、文件内容和命令输出。`0600` 限制其他系统用户读取，但不会阻止当前用户将其提交到 Git。本次没有发现或声称已经发生日志泄露。
- 建议：明确选择日志位置与 Git 排除策略，并修正运行说明的适用范围。可比较仓库外统一存储与工作目录内存储加本地排除两种方案；具体产品选择尚未确认。
- 状态：已复现，未修复。
