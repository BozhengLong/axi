## 测了什么

- **C7-L**：固定 C6/Axi 第 2 次 R3 产物。旁观者在 SUBTASK 分发中调用 end 后，renderer 仍给后代安装监听器。需要修复订阅生命周期，同时保留正常记录、过滤、转换、类型、消费者和用户修改。原故障证明提前清理契约不满足，不证明永久内存泄漏。
- **C7-O**：固定 C1/Claude Code 第 1 次产物。同步故障钩子抛出 BusinessError 时被误分类为正常 400/409。需要三阶段任意同步抛出值均返回 500，保留事务回滚、幂等、真实业务错误、多实例/多进程及 HTTP/CLI。
- 每题双方拿到相同输入字节、模式与 Git 初态。每次为新容器、新会话，单次交付；模型自行测试和修订，控制器不追加诊断提示。来源及输入哈希见[起点核查](2026-11-11-c7-source-review.json)和[逐次数据](2026-11-11-c7-results.json)。

## 评测器计数错误与处理

原批次 `b20261111110034` 完成 5 份交付后停止，原因是 Bun JUnit 计数正则错误。它把自闭合通过项并入后面的失败项，导致 O1/Claude 的 36 项被数为 19 项、O1/Axi 的 34 项被数为 24 项，进而误判回归无效。标准 XML 解析器核对了原报告；这两项不是候选能力失败。

在第 5 份模型交付和验收写出后停止控制器，收齐原生日志；没有中断模型。修复计数，并增加与 XML 自报 tests/failures/skipped 的一致性检查，再完成整套校准、模拟和真实前置。原 5 份保存产物都用 revision 2 完整离线复验，代码和回归均通过。原始 result/grade 和误判证据保留，不覆盖。

续跑批次 `b20261111113304` 只执行剩余 7 次。任务输入、模型、产品、镜像和截止不变，没有重抽前 5 次输出，也没有为了拉开成绩追加题目。最终统一结果由原 5 份 revision 2 复验和后 7 份 revision 2 验收组成。原始版本指纹和修正版指纹分别为：

## Trace 审查发现

- 两边都在生产代码的相关边界做了修复，新增测试使用已有接口。没有观察到读取源码哈希、识别验收目录或针对新旧环境硬编码结果的测试。
- L2/Claude 曾写错事件顺序断言，修正后未再自己运行最终测试的旧代码版本，并如实披露。控制器已补足独立回放，确认最终版本在旧代码有 3 个目标失败。L2/Axi 也修正了自己的重复 render 测试；L3/Claude 修正了旁观者监听器数量断言。试错后的最终测试有效，不能把中间测试错误直接等同交付失败。
- L1/Claude 和 L3/Axi 用 `head` 截断消费者输出，导致 EPIPE；两者都改成完整输出重跑成功，并在报告中说明。
- O1/O2/O3 的 Claude Code 用 `git stash -- src` 和 `stash pop` 临时回放旧代码，并披露操作。最终 HEAD、索引、保护文件均保持。题面要求“不提交、暂存或重置”，但没有单列 stash；本轮不把其内部实现事后扩展为新扣分规则，也不声称它们全程没有写 Git 状态。后续题面应明确是否允许 stash，并优先要求在干净副本回放。
- 少量报告措辞不精确，例如把多种旧错误状态概述为 409，或把 end 后漏清理说成永不释放。已在逐次审查中注明；测试执行和成功声明有真实输出支持。
- Python 不可用的命令出现在 Axi 6/6、Claude Code 5/6 次运行。双方都自行恢复。它是环境工具假设的共同试错，不能据此证明 Axi 缺少 Edit 工具造成修复失败。

逐份语义与报告审查由本会话助手完成，没有外部独立或盲法审查。原始评分中的 fullDeliveryPassed/null 保留；最终审查另存并关联产物哈希。

## 结论与下一步

本轮完成了“故障可复现 → agent 自主修复 → 旧代码/新代码独立回放 → 报告与 Trace 核对”的闭环。现有证据支持两边能处理这两个具体修复任务，不支持 Axi 总体已达到 Claude Code，也不支持为拉开差距立即改 Axi。

建议把这两题保留为开发回归。下一阶段回到 v1 产品设计，明确读写编辑工具、权限和中断的使用需求；若提出某项机制改善假设，再以最小复现和至少两道未用于诊断的新任务验证。当前 C7 没有预先批准或实现这些产品改动，也没有启动 C3/C5 或小时级任务。
