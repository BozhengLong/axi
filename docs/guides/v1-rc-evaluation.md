# v1发布候选验收入口

**本轮已关闭，不要重新运行live或pilots入口。** 开发完整交付1/2，按D3/D5停止；结果见[本轮报告](../verification/2026-11-14-v1-rc-development.md)。以下入口保留用于复查设施和解释原执行顺序，不能据此重置额度。

依据[已确认D1–D5](../10-v1-release-candidate-plan.md)。本轮私有研究目录为`~/.local/share/axi-evals/v1-rc-20261114/`。不要通过旧研究的`--resume`入口启动新版本。

`authorization.json`保存原始授权及18小时绝对截止。`starts/*.json`以独占写入记录真实CLI启动前的额度领取，跨进程不允许复用ID。未到启动点的计划不算已执行；已领取但启动失败的额度不退还。模型任务串行，任务窗口30分钟加评分15分钟，最后30分钟留报告。初始探针三方各一次，开发试跑只使用新候选两次。

当前入口顺序如下。先固定`AXI_RC_STUDY`、`AXI_V1_STUDY`、`AXI_EVAL_IMAGE`、`AXI_V1_IMAGE`和`AXI_V1_NODE_PROFILE=node22`；两个image变量必须为同一个镜像ID。私有`run.sh`记录本轮实际值，不包含凭据。

1. 提交产品和设施后，保存`product-freeze.json`：commit、逐个src文件SHA-256及其有序映射的SHA-256。此后开发两次之间产品与系统指令不变。
2. `bun scripts/eval/rc/offline.ts --offline`执行当前版本单元、类型、环境兼容、已知失败校准、原验收校准、交互、传输、错误协议及封存评分流水线。每项保留独立日志。历史320次稳定性证据仅作为固定Node二进制的来源，不冒充本候选的新执行。
3. 离线门槛通过后，`bun scripts/eval/rc/preflight.ts --live`执行隔离、源码一致性和三方真实探针。每个真实CLI启动分别领取额度。
4. `bun scripts/eval/rc/run.ts --pilots`执行两次已知开发题。每份交付封存，评分在独立进程和新容器运行，最后另做代码、文档及报告人工复核。

正式新题入口仅在开发两次完整通过后准备。任何开发环境中断不重抽；普通交付缺陷也不能通过重抽获得通过。没有独立盲审，不称盲测。

新增验收规则在开发前确定：`js`/`javascript`围栏按完整JavaScript语法检查；原本未修改的块不重复判分；`text`/`pseudocode`围栏不作JS解析。无标记围栏、片段及文档含义由人工复查，不在结果出来后更改分类。语法通过不表示示例运行正确。事件溢出附加检查覆盖抛错属性访问、普通监听隔离、错误终态和清理；原冻结机判保持在旧证据中。

报告审查按实际命令和结果核对，并检查最后修改后是否重跑对应检查。所有工具、退出码、拒绝和取消保留在Trace，不能根据自然语言“通过”自动认定成功。已知报告失败用于校准证据提取，语义判断仍由人工负责。

`execution-seal.json`固定执行输入、产物、Trace及Git状态。`grades/<revision>/<id>/score.json`绑定artifactHash，并分别记录正常失败与不可判定。原始Trace仅私有保存；公开记录提供摘要、哈希和验证范围，不包含真实网关配置或原始工作内容。
