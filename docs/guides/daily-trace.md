# 日常使用 Axi 时的 Trace

按当前v1实现，正常启动交互会话后，Axi会默认记录本地日志。无需开启debug，也不需要运行自动评测脚本。

## 保存位置与生命周期

日志位于**启动Axi时的工作目录**：

```text
<工作目录>/.axi/logs/<UTC时间>-<会话UUID>.jsonl
```

每次启动创建一个新文件，同一进程中的多轮任务追加到这个文件。换一个项目启动，日志就在那个项目的工作目录下，不会统一写回Axi源码仓库。启动画面中的“日志：”会显示实际绝对路径。

文件名和事件时间使用UTC，带`Z`；北京时间为UTC加8小时。JSONL表示每行一个JSON事件。当前事件包含version、sessionId、time、kind和data；任务/工具记录另外关联轮次与工具调用ID。

退出后文件仍然保留。当前没有自动轮转、压缩或定期删除功能，也没有内置Trace浏览器。保存日志不代表支持退出后恢复对话；当前会话历史仍只在本次运行中使用。

实现依据：[日志写入](../../src/log.ts)、[CLI接入](../../src/main.ts)。

## 记录内容

| 内容 | 日常原生日志中的记录 |
|---|---|
| 用户任务与配置 | task_start：输入、effort、权限模式；请求体另包含system、历史消息、模型和工具定义 |
| API请求 | request：callId、尝试编号和实际请求体 |
| 模型返回 | sse：收到的原始SSE文本行；完整响应另写response，包括正文、工具调用、API返回的thinking摘要/签名和用量 |
| 请求错误和重试 | request_error和随后各次request，保留尝试编号、错误原因和耗时；没有独立的完整重试调度记录 |
| 工具调用与结果 | tool_start、tool_end、tool_result：参数、状态、结果和耗时 |
| 自动读取与人工确认 | permission及permission_request：授权来源、允许/拒绝与拒绝理由；自动读取也有授权记录 |
| 文件修改 | proposal、commit_prepared、commit_start、commit_result：差异提案、前后哈希以及适用阶段的提交状态；准备阶段被拒绝的修改不会生成成功提交记录 |
| 任务结束与中断 | task_end、cancel_requested：任务耗时、确认等待时间、取消和已完成修改等信息 |

实现依据：[API客户端](../../src/api/client.ts)、[agent循环](../../src/agent/loop.ts)、[文件工具](../../src/tools/files.ts)。完整模型响应、工具结果与原始SSE会有内容重复，因此日志可能增长较快。

## “都会记录”的边界

日常Trace覆盖agent主要调用过程，但不能称为所有操作的完整录像：

- bash的stdout/stderr合并为工具结果，最多保留30,000个Unicode码点的头尾，省略部分有标记。日志不能补回工具已丢弃的中间输出。[实现](../../src/tools/bash.ts)
- read记录实际返回的分页内容；glob/grep记录实际返回的结果、范围和截断信息。不会自动复制整个仓库，也不会为bash修改的每个文件创建前后快照。
- 不录制终端每次按键、光标变化或完整屏幕。`/help`、`/effort`、`/permissions`等命令没有各自独立的审计事件；后续任务与请求记录反映当时实际使用的设置。
- 不记录认证请求头。服务端未返回的内部推理无法记录；API返回的thinking内容只是服务提供的可观察内容。
- SSE记录解码后的文本行，不保留网络分片或CRLF等行尾字节边界，也不是HTTP抓包。
- 断流时可以有已收到的SSE行，但不会伪造完整response。进程被强制杀死、机器掉电或磁盘写入失败时，末尾记录可能缺失；同步追加不等于断电持久化保证。
- 关键任务或工具日志失败会停止后续操作；已经完成的修改不会因此撤销。仍须根据现场和最后成功记录判断状态。

自动评测额外保存终端输入输出、文件/Git快照、独立验收、校验清单等，这些来自评测控制器，不是日常Axi默认生成的文件。详见[评测Trace指南](trace-reading.md)。

## 本地保存与查看

日志文件以0600权限创建，通常只有当前用户可读写。新建日志目录使用0700；已有目录的模式不会被统一改写。Axi在日志目录维护`.gitignore`，默认忽略日志，不修改项目根目录规则。已经跟踪的文件或强制添加不受这个忽略规则保护。

Axi不会额外自动上传日志文件。任务、已读取源码和工具输出仍按正常对话请求发送给配置的模型服务；本地日志也可能包含这些内容。认证头不记录，不代表用户输入或命令输出中的敏感内容会自动删除。

在启动Axi的目录运行以下只读命令，可按修改时间查看日志文件：

```sh
ls -lt .axi/logs/
```

最直接的定位方式是使用启动画面显示的完整日志路径。排查某次行为时，提供对应路径即可定位该会话，不必把全部原始内容粘贴到聊天或上传到公共仓库。
