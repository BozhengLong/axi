# 哪些 Axi 评测产物需要保留

日常从项目目录运行 Axi 时，原生会话写入该项目的 `.axi/logs/`。本文盘点的是独立的评测目录 `~/.local/share/axi-evals/`。其中既有启动任务时读取的输入，也有结束后才能生成的研究证据。[日常使用说明](v1-first-use.md)

## 按用途判断

| 用途 | 具体文件或目录 | 处理方式 |
|---|---|---|
| 启动和评分 | 候选与基线运行目录、冻结镜像、工具链、题目 `initial/`、输入清单、依赖挂载、公开契约、评分配置、校准参考与基线观测 | 当前批保留在线。某些工具和资格来自旧批，应按实际引用保留 |
| 证明发生了什么 | `formal-controller/controller-events.jsonl`、`runs/<attempt>/` 的输入、初末及检查点快照、评分及审查、`runtime/` 的原生会话、终端 I/O、代理请求及响应分块、封存清单与清理回执 | 保留每次尝试，包括失败和未采用的尝试。由对应批次的 `TRACE-INDEX.md` 定位；单留 Markdown 报告或哈希无法还原 Trace |
| 证明分数可信 | `release-manifest.json`、`admission/`、资格和依赖审计、模拟结果、参考与负例见证、归因回放输入、最终审计 | 与原始证据一起保留。旧批可以转入经校验的归档，仍被新批按绝对路径读取的部分暂时需要留在原位 |
| 可重新生成的副本 | 已结束的任务工作副本和 `seed/`、由快照计算的差异、已下载工具的包缓存、Python 字节码 | 优先审查清理这些项。先确认已封存、原始输入与工具可用，且文件没有被证据清单直接绑定。R5 的 `host-compression-tool/cache/` 是下载缓存实例，工具身份记录另行保留 |

评测目录可能含源码、提示、工具输出以及局部运行凭据。仓库保存脱敏结论与证据哈希，完整可观察 Trace 保存在私有目录。本次仅盘点，没有删除、移动或改写历史产物。
