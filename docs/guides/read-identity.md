# 读取授权与对象身份

2026-11-16。按用户已确认的[方案20/D1–D5](https://github.com/BozhengLong/axi/blob/2114768998a768e1d80ab4a94dce1c4380f919d5/docs/20-p02-identity-repair-plan.md)修复P-02。开发验证已完成，尚不能据此宣称新候选发布验收通过。

read、glob和grep在准备调用时，记录项目根、父路径链与明确目标的身份。strict模式批准的是这份调用，project模式的自动读取也使用同一保护。执行在文件打开、读取分块、目录打开后和返回结果前复核原绑定，不会自动接受替代对象。读取提案只使用一次。

身份变化时，普通替换返回path_changed；目标消失、变成链接等返回相应明确错误。失败结果不带替代内容、文件名或编辑version。需要继续时重新提出调用；strict会再次确认，project生成新的自动决定。若项目根被替换，必须重新启动会话。取消和拒绝仍遵守原有规则。

身份不等于内容版本。同一个文件对象在执行前原地更新内容，仍可读取；read成功后得到的version对应实际读取内容。读取期间内容不稳定仍会拒绝。编辑器若通过临时文件rename保存，则是新对象，旧调用会失效。目录正常增删子项不会仅因时间戳或链接计数变化而失效；搜索不提供整棵目录树的静态快照。

日志新增read_identity_prepared与read_identity_check，通过toolUseId及宿主生成的绑定摘要关联授权。执行中的各核验阶段累计计数，在入口、完成或失效处记录，避免为每个扫描项写一条日志。它们不向模型增加可填写的身份参数。日志依旧可能包含合法读取的项目内容，应按私有数据保管。

本机制是应用层复核，没有操作系统沙箱或文件系统事务。它不承诺检测两次检查之间不可观察的换回操作、任意inode复用，或隔离所有外部竞争写入。已有路径限制、普通UTF-8文件范围、输出上限及bash权限保持。

开发检查包括两平台各五次198项测试、旧C与修复版的110个对照CLI场景、两平台各30个合法内容更新/新授权恢复CLI，以及六类原错误变体和七类身份错误变体。完整发布仍需冻结新C，再完成全部39项工程、两平台干净安装、全题包资格和真实对照。最新结果见[评测分支进度](https://github.com/BozhengLong/axi/blob/codex/v1-tools/docs/progress.md)。
