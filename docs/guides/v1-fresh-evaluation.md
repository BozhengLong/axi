每题三方各三次，共18次，串行运行。新Axi使用auto；旧Axi为963704b，Claude Code保持固定CLI。任务30分钟/50次实际请求，最终与检查点共用15分钟评分。每组三方预留135分钟，再留5分钟准备和封存；恢复预留141分钟加5分钟。研究仍以原授权的18小时时钟为准，不从正式开始重新计时。

真实启动由研究根目录starts台账计数。初始探针3、开发4、C7两次已占9次；基本正式18次后共27次。最多一次合法整组恢复可再用3次探针和3次任务，总上限33。普通失败保留，不因分数不好重抽。鉴权、未知协议、保护/隔离或证据问题停止。

## 运行和评分

新任务的原库、依赖锁、投递快照和完整证据保存在私有研究目录。Node22.23.5、Bun1.3.14及镜像保持。p-retry的原类型工具需要缓存，只有node_modules/.cache使用64MiB临时挂载；所有依赖包仍只读，每次运行的缓存隔离，容器退出后丢弃。

在私有研究run.sh设置正确环境后，入口为：

```sh
bun scripts/eval/fresh/run.ts --check
bun scripts/eval/fresh/run.ts --live
```

只有最终冻结、已推送核对、当前版本离线门槛齐全时，check/live才通过。已有formal.claim不能再次live。不要重新创建授权、清空starts或删除closure来续跑。历史研究保持关闭。

执行与评分分别封存。新Axi在首次复核修改授权前保存检查点，任务结束后才评分，不向运行中的模型反馈保留结果。每组开始以参考实现检查评分环境。代码/新增回归分数与人工完整交付分开记录；模型流程completed不代表独立验收通过。

每个保留场景在独立Node子进程运行。C最多3秒，D最多6秒；父进程同时要求成功退出和实际通过一个目标场景，空报告不会通过。清除继承的NODE_TEST_CONTEXT，避免嵌套测试误用父测试器的内部模式。该变量在[固定Node版本源码](https://github.com/nodejs/node/blob/v22.23.5/lib/internal/test_runner/utils.js#L199)中参与运行模式判定。已知超时为该场景失败；非预期信号/启动错误和外层评分超时单列设施异常。

## 限定恢复与复核

已识别的临时上游故障可触发一次完整三方组恢复，原组三份仍保留，不能只重抽失败的一边。恢复前最多各运行一个三方健康探针。未知或鉴权错误不进入这条路径。

若评分进程异常，控制器停止新增运行并记录grade_repair_required。至多一次批次级评分修复，只允许评分实现变化，执行身份和断言哈希须相同；重新校准和故障注入后，统一重评当前正式批次的全部可评分产物，再用--resume继续未启动部分。不能修候选答案、改验收语义或清空旧评分。旧开发/C7属于已封存的不同任务阶段，不因新题评分变化改写历史结论。

人工复核对三方采用同一公开契约，检查实际代码、有效回归、文档和报告。允许不同实现，不以参考结构作为评分要求。风险归因须有适用证据，未验证判断不得当作事实；已证实的契约缺陷不能靠披露变成通过。当前助手复核不称独立盲审。

原始CLI/API事件、原生日志、工具/权限、检查点、最终文件和Git状态全部私有保留，并用SHA-256核对。公开报告只放脱敏汇总。完整指可观察渠道齐全，不包含服务端未返回的内部推理，也不消除工具自身的输出截断。
