# 有界收尾复核

依据[已确认D2](../11-v1-delivery-review-plan.md)。当前实现仍待开发对照及发布验收，不能把功能实现当作v1已发布。

默认模式是`auto`。本轮有文件修改或获准执行bash后，Axi会在交付前复核一次。普通问答、仅文件读取和全部被拒绝的操作不触发。

```text
/review        查看当前模式
/review auto   开启自动收尾复核
/review off    关闭自动收尾复核
```

模式在任务开始时固定，下一轮可改变；只保留在当前进程。模型不能修改这个模式。复核中的bash和文件修改仍要逐次确认，拒绝理由继续有效。Ctrl+C结束当前任务，已经完成的修改保留。

开启时正常阶段最多40次生成请求，复核最多10次，总计不超过50次。关闭时整个任务最多50次。每次重试也占一次额度。计数发生在客户端的请求尝试处；连接或日志故障时，不能仅凭本地计数证明上游已经接收，评测另用转发记录核对。

正常回答的初稿是过程输出。界面显示“待复核初稿”后进入“收尾复核”；达到40次工作请求时，会在完整工具配对结束后进入“工作中检查点”。后者不代表模型已经完成任务。预算、日志、协议或中断问题会明确结束为未完成，不会开启新任务重新获取额度。

复核要求核对契约、实际修改、验证证据和重大风险判断。例如，“旧问题”需要可信基线对照；不能把Git HEAD冒充用户已经修改的版本。已有且仍适用的检查可以复用。若已确认违反任务要求，应在预算内修复并复验，或明确说明未完成。

一次复核仍由同一个模型执行，可能漏掉问题。原生`task_end.outcome=completed`表示模型流程完成，不表示代码通过了独立验收。

新增原生记录包括`review_start`、`internal_input`、`review_end`和任务结束状态；API请求记录含阶段预算。自动复核消息明确标为Axi生成，历史仍只追加。评测侧在允许任何复核修改前保存检查点，并分别封存最终产物、Git状态和原始Trace；检查点评分在模型任务结束后进行，不给模型返回保留验收答案。
