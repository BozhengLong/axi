# 自动收尾复核

一次收尾复核来自[原D2](../11-v1-delivery-review-plan.md)。2026-11-17，用户确认[新D1/D2](../21-unbounded-task-execution.md)，取消其中的40/10/50次配额。文件名保留以兼容已有链接；当前实现仍待新候选正式验收，不能把功能实现当作v1已发布。

默认模式是`auto`。本轮有文件修改或获准执行bash后，Axi会在交付前复核一次。普通问答、仅文件读取和全部被拒绝的操作不触发。

```text
/review        查看当前模式
/review auto   开启自动收尾复核
/review off    关闭自动收尾复核
```

模式在任务开始时固定，下一轮可改变；只保留在当前进程。模型不能修改这个模式。复核中的bash和文件修改仍要逐次确认，拒绝理由继续有效。Ctrl+C结束当前任务，已经完成的修改保留。

工作、复核及整个任务都不设请求次数上限。重试仍计入尝试数。计数发生在客户端的请求尝试处；连接、取消或日志故障时，不能仅凭本地计数证明上游已经接收，评测另用转发记录核对。

符合条件的正常回答初稿是过程输出，随后进入“收尾复核”。不再因达到某个请求数强制切换阶段。复核只进入一次；复核的正常回答结束本轮。连续故障恢复窗口、日志、协议或中断问题会明确结束为未完成，不自动重放整个任务。窗口规则见[运行与重试](task-execution.md)。

复核要求核对契约、实际修改、验证证据和重大风险判断。例如，“旧问题”需要可信基线对照；不能把Git HEAD冒充用户已经修改的版本。已有且仍适用的检查可以复用。若已确认违反任务要求，应修复并复验，或明确说明未完成。

一次复核仍由同一个模型执行，可能漏掉问题。原生`task_end.outcome=completed`表示模型流程完成，不表示代码通过了独立验收。

原生记录包括`review_start`、`internal_input`、`review_end`和任务结束状态；API请求记录含阶段计数。版本4保留字段名`budget`，但其中`unlimited=true`、`remaining=null`，不再代表剩余额度。自动复核消息明确标为Axi生成，历史仍只追加。已有评测脚本按旧候选冻结，尚未为此开发版本重新取得资格；不能直接复用旧预算解释或宣布新版本通过。
