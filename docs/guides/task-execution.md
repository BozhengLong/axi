# 任务运行与故障重试

适用于`codex/v1-unbounded-tasks`开发版。产品决定见[设计D1/D2](../21-unbounded-task-execution.md)。

## 三种不同的限制

| 范围 | 当前行为 |
|---|---|
| 整项用户任务 | 不设固定模型调用次数、总时间、总Token或总金额上限。工作阶段和一次收尾复核均不限请求次数。 |
| 一次逻辑模型调用 | 获取一个完整模型响应的恢复窗口默认10分钟。窗口内可多次尝试；成功后下一次模型调用独立计时。 |
| 单次HTTP请求 | 最多5分钟，并取恢复窗口剩余时间的较小值。工具超时和权限规则保持。 |

例如，一项任务可以先完成80次调用，随后第81次遇到限流。此前80次不会消耗第81次的恢复窗口。第81次从首次尝试起计算请求耗时和退避等待；完整成功后，第82次重新计时。窗口不包含其他工具运行或用户确认等待。

这里的不限次数不会取消服务商的限流、账户配额或模型上下文容量。当前没有上下文压缩，也不支持退出后恢复会话。

## 运行配置

默认无需新增配置。若要将每次逻辑调用的恢复窗口设为60秒，在已配置API环境变量的终端运行：

```sh
AXI_RETRY_WINDOW_MS=60000 bun run /你的路径/axi/src/main.ts
```

取值为1至2147483647的整数毫秒。启动画面会显示实际窗口。10分钟是本次实现选定的默认值，不是用户指定的固定业务门槛。

429、5xx及已识别的临时网络错误可以恢复；认证和协议错误等不可重试问题立即报告。默认退避为1、2、4、8、16、30秒，之后最多30秒；有效`Retry-After`优先。若服务端要求的等待已超出剩余窗口，Axi等待到窗口截止后停止，不提前发送。Ctrl+C可以立即中止退避或当前请求。

窗口到期显示“本轮未完成”，回到输入框，保留已经修改的文件和`.axi/logs/`。你可以在同一会话提出下一项任务；Axi不会自动重放旧工具或撤销修改。保存Trace不等于可以在重启后恢复任务。

## 计数与追踪

日志版本为4。`request`按尝试计数，包含重试；`response`只记录完整成功的模型响应。两者不是同一个数字。重试沿用同一`callId`及请求体，失败或半截响应不追加为历史中的assistant消息。

`budget`保留工作/复核计数字段，并使用`unlimited=true`、`remaining=null`。`retry_scheduled`记录等待与剩余时间，`retry_exhausted`记录窗口结束；对应`task_end.outcome=retry_exhausted`，不能解读为任务成功。

日常Trace的内容与限制见[日志说明](daily-trace.md)。旧评测中的时间、次数和资源限制属于外部实验规则；不能直接当作新版产品的默认行为。旧批次不续跑，新正式验收须单独冻结方案。
