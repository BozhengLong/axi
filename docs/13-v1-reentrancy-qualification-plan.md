## 1. 判断与目标

下一轮先取得可靠的参考与判据，再检验一种具体的边界检查方法，最后回到原发布门槛。四次运行没有证明加长提示可以提高完整交付率，也没有证明通用复核无用。样本太少，不能作总体推断。

| 已核对事实 | 判断及限制 | 下一轮动作 |
|---|---|---|

| E旧调用在cache.has中被删除失效，返回后又登记自己 | 同步回调可以在第一个await之前重入；不能把调用用户代码的片段视为不可打断 | 核对调用前、回调中、返回后、发布及清理的状态 |
| 两套参考在异步函数调用返回后都只检查hasSettled，再登记Promise | 两套实现共享了同一处危险流程；数量和其他结构差异不能证明判据可靠 | 由公开行为定义判据，并验证不同登记机制的合法实现 |

| D13把原生once自动移除漏计，合法实现被误判 | 检查应观测实际资源状态，不能要求特定清理调用 | 保留原生once正例，审计其他对实现方式的无依据约束 |
| 四次均实际复核，最终生产文件与检查点一致 | 复核有实验和验证，但未消除E缺陷；不能只凭复核执行过就放行 | 检查是否取得能暴露相关错误的行为证据 |

这里的“重入”指库调用用户回调时，回调又调用该库；它不需要另一个线程，也不需要先发生await。“状态发布”指把计算结果或进行中的调用登记为后续调用可以使用的状态。

目标仍是：Axi在声明的任务与预算内，能交付符合契约的代码、有效回归和准确报告。修好评测参考不等于修好Axi，人工修复产物也不计模型成功。有限验收不能证明任意程序正确，但已确认的契约缺陷必须阻止发布。

本轮阻塞证据来自生成的任务代码、参考和测量。尚无证据可把这些缺陷归因到Axi文件工具；也不能由此推断工具没有其他缺陷。

## 3. D1：从公开行为建立重入资格

### 3.1 先写不变量

不变量是每条合法执行路径都必须满足的条件。它描述外部行为，不要求生产代码采用某种Map、token或计数器。

E至少覆盖以下条件：

1. 有效删除生效后，新调用不能加入删除前的旧工作。
2. 旧工作被失效后，不能重新发布为可复用调用，也不能取得新的写回资格。
3. 新调用必须等待适用的同键删除；等待中发生的后续删除也要按公开约定处理。
4. 已开始的写入在删除前完成；登记和发布不能漏掉回调内部发起的删除。
5. 旧调用只能清理自己的登记，不能移除后来调用的状态。
6. 不同键、不同缓存与共享缓存函数的作用范围符合公开约定。
7. 错误身份、回调接收者和适用的Promise观察语义保持；无新增未处理拒绝。
8. 完成或失败后能释放库持有的资源；不能用固定GC次数代替释放证据。

先明确调用进入、键解析完成、删除生效、状态发布和清理的含义。特别是键计算过程中发生重入时，必须先说明哪些调用应视为失效前工作。遇到原题表述不足的组合，先形成明确的新开发契约再评分，不在看完模型结果后补定义；无法确定就阻断准入。

### 3.2 建立有限调度矩阵

| 维度 | 需要检查的范围 |
|---|---|
| 外部代码入口 | cacheKey、cache.has/get/set/delete、业务fn、shouldCache；包括适用的属性读取 |
| 时点 | 同步调用栈内、首次挂起前、挂起后、恢复后但发布前、清理期间 |
| 重入动作 | 同键新调用、删除、clear；不同键及共享缓存的对照 |
| 返回和错误 | 普通值、原生Promise、thenable、同步抛错、拒绝、会抛错的属性访问 |
| 交错 | 一层重入，以及公开契约支持的两次删除/有限嵌套；成功与失败释放 |

矩阵不是把所有格子机械组合。准备阶段列出适用组合、排除原因和覆盖缺口。用户自己形成的等待环继续排除，不能把它当库的必解问题。

采用两层检查：

- 定向反例：本轮最小复现、相邻发布时点、失效后旧清理、已开始写入、失败后的后续调用等。
- 有限状态模型：用简化的调用身份、有效性和事件顺序描述契约。以可控的完成信号推进执行，生成固定种子与固定清单的短序列。首版上限建议256条有效序列、最多两键/两函数/两层重入。先满足已声明关键组合；预算内覆盖不足就不准入，不把被截掉的组合称已覆盖。

模型只给出允许的公开结果和先后约束，不复刻参考实现，不调用参考业务helper，不要求任意内部步骤数或相同微任务编号。新能力没有原库正例时依据公开契约；应保持的旧行为再用相同输入对照可信原态。

运行前固定序列、预期、分类及时间规则。出现反例时保留原序列，再提取最小复现。不得筛掉失败种子后只报告成功部分。每个适用单元都要能追溯到已执行用例；“没有反例”只代表该有限范围。

## 4. D2：重建参考与评分资格

### 4.1 修的是一类状态问题

在新命名空间修参考，不覆盖已关闭研究的文件和成绩。审查所有向用户代码转交控制权的地方，以及回来后的登记、写回和清理。人工最小修复的版本检查只是起点，不能假定加在现有那一行就覆盖了所有入口。

保留至少两套在登记/失效机制上有实质差异的合法实现。例如，可分别探索先建立调用所有权，以及返回后验证状态再发布；两者都必须先证明兼容，不能预设它们一定正确。只换名称或共同保留同一外层登记流程不算这一层差异。

两套实现都必须通过原构建/运行/类型、全部契约、重入矩阵、文档示例及有效回归。重点防止为了提前登记而新增错误的Promise吸收、属性访问、接收者或时序变化。不同正确实现不必有相同内部结构。

### 4.2 判据不能由参考投票决定

检查依据来自D1的契约模型。参考是被检验对象，不是真值来源。参考不一致时先定位，不取多数意见。由同一助手完成的检查不会称为独立盲审；程序实现分离也不等于人员独立。

正例至少包含：不同登记机制、显式移除监听器、原生once自动移除。负例至少包含：失效后重新登记、未等待已开始写入、旧清理覆盖新状态、改变接收者、错误观察原生Promise、遗留真实资源、恒真回归及仅导入失败的回归。

资源检查优先读实际状态。还应审计固定unref调用次数、显式remove次数等是否只是参考实现的习惯。本轮已证实的是once误判；其他点在审计前仅是风险，不能称为新发现的误判。若不需要创建某个计时器，不能因没有相应unref调用就判错；对实际创建且应unref的计时器仍须验证行为。

默认Node退出检查与带观察器的定位诊断分开，不能用全局兜底或跳过路径得到通过。

### 4.3 离线准入

- 回放本轮四份最终及四份检查点，另回放既有八份历史资格快照，共16份模型封存视图。原分数保持；新结果只作资格材料，不算模型重跑或新成功。
- 两份旧E参考及人工最小修复副本单列。它们不自动获得新版本正例身份。
- 原测试和所有完整正例各完成5次预定重复。生成序列的范围、种子和预期先声明，失败全部保留。
- 合法替代实现必须通过，已声明错误变体必须被相关行为断言检出；超时、取消、空报告和信号退出不得假装普通失败。
- 保留15分钟共享评分预算、缓存重建、worker回收、停止/排空等现有故障检查；覆盖实际执行的测量脚本，不能只验证原始模板。

全部通过后才开始真实探针。若还存在无法解释的参考分歧、合法实现误判或重复不稳定，就不准入。准备时间仍计入新研究总时钟。

## 5. D3：把通用复核落到可执行证据

假设：明确控制权转交与状态发布边界，再取得一条会失败的相关证据，可能改善此类任务交付。该假设尚未得到验证。

建议以0330626为控制版，新候选也从该版本构建；上一轮未选定的提示实验另存留证，不直接层层叠加。只调整通用工作与一次复核协议，不引入v2会话功能、新agent、额外复核轮次或自动授权。

有相关改动时，要求Axi用简短、可核查的记录回答：

1. 哪个外部回调、等待返回或状态发布可能让此前假设失效？
2. 进入前和返回后，必须保持什么可观察条件？
3. 哪条可终止的输入/调用顺序会让一种合理的错误实现暴露？
4. 实际执行了什么检查，结果是什么？未覆盖什么？

代码已正确时，可以复用适用证据。缺证据时补针对性检查。发现违约时修复并复验，来不及则明确未完成。对没有这类边界的任务说明不适用，不机械新增测试。

这套记录仍用现有工具和追加式历史实现，不新增一个声称“已验证”的工具或机械勾选门禁。评分不按是否填表、日志长度、GC次数或测试数量放行，要看真实行为证据。通用提示不含E/D名称、保留输入、最小复现或具体修复代码；开发题公开条款与两版输入相同。

预算保持：一次auto复核，工作最多40次、复核最多10次实际请求，总数50，重试计入；任务30分钟。E当前→候选、D候选→当前，共四次，开始前固定两版，中途不调参或反馈保留结果。

选择规则保持：完整交付要求代码、有效回归、文档/报告、实际复核和保护均通过，且没有已确认契约缺陷。当前版完整2/2就保留当前；否则候选完整2/2才选候选；都不合格则停止。人工修复参考不能填进模型成绩。

E/D已经暴露，2/2只用于开发准入，不代替新题迁移证据。模型不获得参考实现或诊断补丁。

### 7.2 明确冻结对象

新研究分别记录并关联：

- 执行身份：输入、产品、CLI、模型档位、镜像、依赖、权限及任务预算。
- 契约与判定清单：公开条款、场景输入、允许结果、预期值、分类规则和时间边界。
- 测量实现及实际执行脚本：包括所有适配变换，不能只给原始模板哈希。
- 评分版本：完整绑定本次实际使用的上述材料、运行设施与产物哈希。

进入真实开发后，最多一次评分实现修复。只有执行身份和契约判定不变，才能修测量、解析、重建或清理。必须先保留复现，说明为什么是误测，再用合法正例和真实错误变体验证，重新资格后统一重评该研究所有已封存可评分产物。旧分数保留，不重跑模型。

测量修复允许产生新的执行脚本哈希，必须明示。不能因为原模板没变就声称实际检查没变。更改场景、预期结果、允许行为或必需门槛属于规则变更，不得伪装成测量修复；需要新设计和新的正式统计。再次出现无法可信判定的评分设施问题则结束研究。

### 7.3 停止与证据

开发无合格版本、C7未完整2/2、正式新v1明确失败、时间不足，均按对应阶段停止。保护、隔离、鉴权、未知协议或证据完整性问题立即停止新增；有扩大风险时才中断在途，否则在原预算内完成封存。评分不可信时阻断评分，不以旧成功记录补位。
