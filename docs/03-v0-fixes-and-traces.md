## Trace 的含义

这里的 trace 指可观察的运行轨迹：任务输入、模型请求、返回内容与事件、工具参数和结果、权限决定、错误与重试、CLI 输入输出、文件快照、验收结果，以及源码和配置标识。

API 返回的思考摘要与签名属于可观察响应，可以保存。服务端没有返回的内部推理过程不能取得。工具自身已截断的内容不能被控制器还原。认证头和真实 key 不进入共享记录。

## 后续批次的保留方式

- 每次输入、输出、中断和进程结束记录时间，保留原始终端字节或结构化 CLI 消息，并单独保存 Claude Code stderr。
- 容器清理前冻结进程，导出 Axi 的原生会话日志，以及 Claude Code 的原生会话记录和调试日志。只收取明确的日志路径，不复制认证配置。
- 每轮生成清单：路径、字节数、SHA-256、收取状态和缺失原因。超限或未完成时明确标记，不把部分记录称为完整。
- 每批在开始前保存源码快照与任务清单。输出时间线索引，能从模型调用找到权限、工具结果与验收文件。
- 原始记录保存在私有目录，目录权限 `0700`、文件 `0600`。清理测试容器不清理这些证据；本轮不设置自动删除期限。
