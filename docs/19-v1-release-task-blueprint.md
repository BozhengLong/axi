# v1正式验收：20题覆盖蓝图与顺序

2026-11-16。状态：**设计稿，未选定具体仓库/commit，未制作参考或运行模型。** 从属于[候选冻结与正式验收方案D4](19-v1-release-acceptance-plan.md)。这里固定任务类别、覆盖槽及顺序，不冒充已经取得资格的20道题。

## 1. 怎样把蓝图变成真实题包

先冻结产品P、交付候选C、模型和基础环境，再将每个槽绑定真实仓库、完整提交、问题来源/需求依据和不可变初态。A–H是八个不同上游仓库的占位组；A–D各3题，E–H各2题。允许拆分为更多不同仓库，但不得合并得少于8个或让一个仓库超过3题。不能把fork当另一个独立仓库。

每个槽的主题是推荐选题方向。若找不到可信、适配且有用户价值的任务，记录拒收原因；在准备窗口内按同一类别/覆盖要求重新选择。正式冻结后不换题。具体事件、输出、错误分类和H4约束以运行前公开题包固定，不在看到结果后增补要求。

“脏改：生产”表示必须保留目标仓库生产文件中的用户既有修改；“用户文件”表示至少含明确的用户未提交内容。它们不都是整文件只读：任务需要改同文件其他区域时，按冻结的用户差异保护。“异步”表示任务必须实际覆盖普通异步/取消/并发/资源场景，不只在题面提到。

|---|---|---|---|---|---|---|

蓝图当前满足4类各5题、8个仓库组且每组≤3题；12题含脏改，其中4题在生产文件；14题明确含异步场景。具体题包冻结时重新计数，不能只以本表代替实际证据。

这些主题不允许复用旧Listr2/C7订单题、p-memoize、p-retry或其他已暴露任务的实现/验收作为新题。普通缓存、取消等概念可以出现，但仓库、需求及原因链须独立，不能复制旧压力题换名称。

H1/H2/H3/H5通用约束对所有任务生效。H4的关键业务/数据约束逐题在公开包中注明：例如取消后不得继续特定副作用、写入不得破坏原文件、重试不得重复约定操作。不能把该题所有普通逻辑错误都叫H，也不能事后把已冻结的H4降为N。

## 3. 三方执行顺序

记O＝固定v0，N＝冻结v1候选C，CC＝Claude Code。三方都使用相同模型档位与30分钟/50请求上限。顺序预先固定，避免按前一题表现安排后续。

| 任务 | 顺序 | 任务 | 顺序 |
|---|---|---|---|
| T01 | O→N→CC | T11 | CC→N→O |
| T02 | N→CC→O | T12 | N→O→CC |
| T03 | CC→O→N | T13 | O→N→CC |
| T04 | O→CC→N | T14 | N→CC→O |
| T05 | CC→N→O | T15 | CC→O→N |
| T06 | N→O→CC | T16 | O→CC→N |
| T07 | O→N→CC | T17 | CC→N→O |
| T08 | N→CC→O | T18 | N→O→CC |
| T09 | CC→O→N | T19 | O→N→CC |
| T10 | O→CC→N | T20 | N→CC→O |

每方在三个位置各出现6或7次。执行按T01到T20顺序，而不是按表左右列逐行穿插。三个会话和工作副本独立，前一个产物和隐藏评分不反馈给后一个。普通失败仍完成该组三方；H/不可信评分按主方案全局停止。

## 4. 正式manifest不得缺少的内容

每个槽实际绑定后，至少记录以下字段并通过校验：

- `taskId/category/repository/upstreamCommit/sourceArchiveHash`：真实项目与固定源身份；上游仓库的独立性分组。
- `selectionEvidence/exposureAudit/userValue/moduleSpan`：来源、未用于调产品的核对、用户价值及理解跨度。
- `initialFiles/initialGit/userChanges/protectedRegions/allowedPaths`：三方同一接手状态；生产脏改保护规则能接受合法修复。
- `publicBrief/requirements/allowedResults/criticalConstraints`：公开语义、允许结果和预先确定的H/N等级。
- `commands/baselineTests/preExistingSkips/dependencies/environment`：实际版本与完整命令、用例数、原有跳过及工具缓存边界。
- `references/negativeControls/qualificationRuns`：两套合法实现、对应错误变体、5次重复及真实CLI模拟证据。
- `graderRevision/evidenceSchema/gradeBudgetMs`：实际评分源码、断言与进程状态区分、最终/检查点共享预算。
- `exampleExecution/reportRequirements`：需要实际运行的示例、本地替身边界、报告必需事实。
- `executionOrder/requestLimit/deadlines`：本表顺序、固定预算、单槽唯一claim及绝对截止。

选题和参考资格全部完成后发布脱敏目录与冻结哈希。原始参考、保留检查和完整Trace仍私有，防止传给被测模型。缺字段、覆盖不足、参考分歧、正例不稳定或错误变体未检出时，该题不准入；全部20题齐备前不启动真实探针。
