# Axi 官方安装器预览方案

2026-11-20。用户认可采用和 Pi 类似的官方安装体验。本方案给出首批交付、安装行为和验收条件。D1–D5 待用户确认。

## 目标与现状

从官方 GitHub 发布页执行一次安装命令，随后在项目目录输入 `axi`。用户可以确认安装版本、升级并恢复上一版。用户使用自己的模型网关和密钥。

`v0.0.1` 已公开提供源码包。可行性验证使用这份源码与 Bun 1.3.14，分别在 macOS ARM64 和 Linux ARM64 容器编译出独立可执行文件，并在未配置 API 凭据时运行 `--help`。这个验证覆盖构建和帮助入口。真实安装、更新和下载后启动仍待实测。[v0.0.1 试用记录](verification/2026-11-20-preview-v001-and-v28-scoring.md) · [Bun 编译文档](https://bun.com/docs/compiler)

Pi 提供项目维护的安装器和包管理入口，安装后使用 `pi` 命令。Axi 首批采用 GitHub Release 和安装脚本，使发布件、安装说明和版本关联在同一处。[Pi 官方安装说明](https://github.com/earendil-works/pi#getting-started)

| 决策 | 推荐做法 |
|---|---|
| D1 预览版本和平台 | 预留 `v0.0.2`。先验证 macOS ARM64、Linux x64 和 Linux ARM64。各平台只在其实际下载件验收通过后列为可安装。 |
| D2 构建与来源 | 固定源码提交、Bun 版本和依赖锁。构建单文件 `axi`，随发布件提供源码身份、平台和 SHA-256 校验值。 |
| D3 安装、升级与恢复 | 版本固定的一条命令，安装到当前用户目录。升级由用户主动触发。保留上一版，可显式切回。 |
| D4 首次启动 | `axi --version` 与 `axi --help` 可以离线运行。首次使用指南说明模型网关配置和试用步骤。 |
| D5 发布准入 | 在干净环境中验证真实安装、代表性任务、卸载和恢复。先完成 macOS 下载信任验证，再公布 macOS 安装入口。 |

## D1–D2 交付与构建

- 从新的预览候选提交构建。使用锁定的 Bun 和依赖，把运行时与 Axi 打进单文件。保留 GitHub 源码下载和按平台打包的可执行文件。候选的源码提交、工具版本、操作系统与架构、最早实测系统版本和发布件哈希写入构建回执。
- 构建和测试在已登记的对应平台上运行。Linux x64 需有实际执行证据。macOS 发布件经过签名和公证流程后，再生成最终下载校验值。每个版本只声明已核实的平台；Intel Mac 与 Windows 的支持根据后续实测补充。
- 安装脚本按明确版本下载，对照该版本的制品名和校验值。先校验归档再解包，仅接受预期的普通可执行文件。发布件与日志中均使用可公开信息，凭据和原始验收 Trace 保存在私有目录。当前预览不绑定 npm、Homebrew 或额外域名。

## D3 安装、升级与恢复

- 官方命令从对应 GitHub Release 读取安装脚本。脚本识别系统与架构，在临时目录下载制品，完成哈希和版本检查。校验成功后，安装到当前用户目录。版本文件可放在 `~/.local/share/axi/versions/`，命令入口为 `~/.local/bin/axi`。
- 更新采用同一个安装命令并显式指定目标版本。校验新版本可执行文件后，原子切换命令入口，保留此前版本。对同一版本重复安装应得到同一结果。更新失败或中断时，已启用的旧版本仍能启动。
- 试用者通过安装器显式选回已安装的旧版本。卸载只处理安装器登记的版本与命令入口；项目日志、用户配置与凭据由本人管理。既有 `axi` 命令与本安装登记不匹配时，提示冲突并停止。脚本使用当前用户权限。PATH 缺少安装目录时，提示可复制的设置命令。

## D4 首次使用

1. 安装后用 `axi --version` 核对版本和源码提交。用 `axi --help` 查看命令。两条命令在配置模型前即可使用。
2. 试用者设置自己的 `ANTHROPIC_BASE_URL` 和 `ANTHROPIC_API_KEY`，使用支持候选固定模型的 Anthropic Messages 兼容网关。缺配置时显示准确的缺项和指南位置。
3. 从有提交基线的临时 Git 仓库运行 `axi`。先启用 `/permissions strict`。指南说明审批四步、Git 回退和 `.axi/logs/` 的位置。[预览指南](https://github.com/BozhengLong/axi/releases/download/v0.0.1/PREVIEW.md)

## D5 验收条件和发布范围

| 检查 | 通过条件 |
|---|---|
| 下载与新装 | 从与公开发布一致的入口安装。干净账户未安装 Bun 或项目依赖。命令能启动，版本和哈希与候选一致。 |
| 真实首用 | 每个拟发布平台用安装所得的 `axi` 连接已授权网关。验证读取确认、预览、一次批准写入和一次拒绝写入。比对 Git HEAD、索引及拒绝目标，核对原生 Trace 可读。 |
| 升级与回退 | 用带版本的旧测试制品安装，更新至候选，随后切回旧版。各阶段命令指向正确版本，原项目文件和配置可继续使用。覆盖重复安装、两个安装进程并发、已有同名命令及卸载。 |
| 失败处理 | 断网、损坏或错误架构的制品，以及安装中断，均返回明确结果。验证已有入口仍能启动，首次失败安装不留下有效命令。 |
| macOS 下载信任 | 用 Developer ID 签名目标可执行文件，核对签名和所需运行权限，再提交 Apple 公证。用干净账户从浏览器下载最终交付件，实测 Gatekeeper 和首次运行。 |
| 公开核对 | 发布前检查附件哈希、真实下载件、支持平台和试用说明。发布后匿名重下，核对哈希和版本。 |

当前 Mac 有 `notarytool`。在本机当前钥匙串未查到可用的 Developer ID Application 签名身份。实施阶段先确认可用的签名环境。Linux 的验收可独立进行。macOS 公布安装入口前须完成签名、公证和真实下载启动。[Apple Developer ID](https://developer.apple.com/developer-id/) · [Apple 公证流程](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow)
