## 3. 外部时间窗口与次数口径（D2）

“逻辑模型调用”是获取一个完整响应的过程；“请求尝试”包括失败重试；“真实CLI启动”是一次独立模型会话；“逻辑槽”是某题的某个产品。四个数字必须分开。

| 边界 | 规则 |
|---|---|
| 日常Axi产品 | 不设整项任务总次数、总时间、总Token或总金额上限；本方案不向产品注入30分钟任务停止逻辑 |
| 正式任务与C7 | 从该次claim起30分钟，包含环境启动、模型、工具、确认控制器和重试等待，不扣掉429耗时；不因重跑保留旧历史或部分产物 |
| 健康探针 | 每次claim起3分钟执行，后续封存/评分/清理最多5分钟；是出口和执行路径检查，不验证10分钟完整恢复窗口 |
| 结束与评分 | 到执行截止关闭新的代理转发、发送中断，最多5秒后强制终止仍存活的被测进程；普通任务/C7的封存、最终/检查点评分、清理共用后续15分钟；健康探针按上一行5分钟，模型不得继续工作 |
| 请求总数 | 代理接收、转发准入、完整响应、错误、count_tokens分别计量。`requestLimit=null`且`limitMode=unlimited`；缺少配置视为未准入，不能`null ?? 50`回落 |
| 资源 | 请求体、内存、文件、磁盘等仍有显式实验边界，写入manifest；不能用任意大整数伪装不限次数，也不能因计数高静默停机 |

当前旧转发器有16 MiB请求体等资源边界。F3必须盘点并声明这些边界，禁止把本地拒绝包装成上游429。保留三方相同的16 MiB单请求体界限；达到时按设施资源中断留证，不能声称是模型任务N或用网络恢复机会重跑。它不属于日常Axi产品限制。

30分钟内已经恢复的临时故障不使样本自动无效。任务正常结束后按产物评分；到截止仍未完成且没有正在阻止运行的确证外部故障，记N/`task_timeout`。这测量固定墙钟下的交付，不宣称“没有任何429时也一定失败”。报告同时列出故障次数和等待，便于理解边界。

若截止时正处于确证外部故障链，或产品因该故障链停止，按第4节处理。不得仅凭终端“额度”“超时”“retry_exhausted”字样判断原因。

## 4. 外部故障、重跑与不可判定（D3）

新增`ENV_INTERRUPTED`只表示有证据的外部中断；它不等于能力N，也不是成功。`UNKNOWN`表示证据或原因不足，不能自动进入环境恢复。

| 实际情况 | 分类与处理 |
|---|---|
| 429/5xx/暂时断连后恢复，最终完整交付 | 正常评分PASS/N/H；记录故障，不补跑 |
| 正常交付有缺项、无故障时超时、原生次数限制/上下文限制结束 | N；普通失败不补跑。若满足冻结H条款则按H |
| 代理保留上游限流/可重试服务错误或可定位的外部传输失败，且它直接导致终止或持续至截止 | ENV_INTERRUPTED；先检查副作用/H与完整Trace，再进入有界恢复 |
| 只有retry_exhausted/超时文字，没有外部见证；协议异常原因不明 | UNKNOWN，暂停；不能靠补跑消除未知 |
| 鉴权失败、固定型号不可用、身份漂移 | 准入/配置失败，停止新增并收尾；不自动换key、型号、CLI或网关设置 |
| 磁盘不足、Trace截断/缺失、封存失败或设施超时 | 设施异常/UNKNOWN；不得记能力N，不使用网络恢复机会 |
| 确证H1–H5中的产品违规 | 全局停止；即使同时存在限流，也不撤销该违规 |

外部中断见证必须绑定`runId/callId/attempt`、上游响应或宿主传输事件、时间线、原生终态（若有）、代理关闭记录和文件封存。需要证明错误来自外部，且候选没有在上游已成功时误报失败。DNS或断连无法定位时保留UNKNOWN。历史样本出现429不等于当前槽也遇到同一原因。

恢复流程预先固定：

1. 原始尝试先封存为`attempt=1, ENV_INTERRUPTED`，保留全部已执行内容和保护审查。没有完整证据，不能恢复。暂停新增任务；不关闭整个批次，也不修改已结束的其他槽。
2. 全批最多登记2个恢复事件，每个逻辑槽最多1个。恢复准入窗口从登记时起最多1小时，涵盖冷却、健康检查和重跑授权；重跑另用该槽原定执行/评分窗口。不重置T1、正式或总截止。先固定冷却15分钟，再执行一次v0→v1→Claude健康检查，各最多3分钟执行加5分钟封存/评分；三条均正常完成且没有临时上游错误才准许重跑。健康检查不循环到成功。
3. 原槽使用`attempt=2`、新claim、新会话和全新初态，仍为同一候选/题目/模型/F。只重跑受影响产品；同题另两方已经得到的PASS/N保持，未启动的按原顺序继续。时间间隔公开报告。
4. attempt=2正常结束后，按原契约评分。即使是N也接受，不再跑。再次外部中断、恢复探针失败、第三个恢复事件、窗口或总时间不足，结束为INCOMPLETE；已有确定必要条件失败时为NO-GO并列出未决项。
5. H、普通N及缺失证据不能因先看到结果再改叫外部中断。正在失败的测试、缺文档等部分产物仍归档，但未正常交付前的临时状态不自动当作最终N；已成立的保护违规仍阻止补跑。

统计采用每个逻辑槽**第一份有效、证据完整的尝试**，可判PASS或N；N不要求任务已经完成，也不因此获得重跑资格。没有有效尝试的槽一直是未决，不能从60份分母删除。只有满足以上资格的ENV_INTERRUPTED才可由第二次补齐。另报告全部首次尝试的完成率、环境中断率、全部尝试次数/耗时/请求数及补跑前后结果。不能只展示补跑后的通过率，也不能用这组数据宣称真实使用中没有中断。

| RT02 | 第40/50次HTTP 429及流内限流可恢复；重试请求快照相同；不追加半截消息、不重复工具副作用 |
| RT03 | 持续429/5xx/传输失败按窗口截止；成功后下个逻辑调用重新计时；长Retry-After不提前发送，迟到响应不算成功 |
| RT04 | 请求、退避、复核中取消停止；完整工具配对和文件保留；下一用户回合可继续；日志失败不误当网络错误 |
| RT05 | Trace v4字段/计数/阶段/终态与代理一一关联；本地未发送的尝试有明确原因，不强迫它等于实际转发数；缺记录或重复记录被拒绝 |
| RT06 | 三方代理均无次数阈值；v0原生50逻辑调用限制保持且正确识别；Claude启动参数不添加max-turns；旧r2预算模拟仍按旧值停止 |
| RT07 | 超过30分钟的新请求被代理拒绝，运行中连接/进程被停止；重启控制器或主机时间回拨不延长deadline，封存和评分中不能继续模型工作 |
| RT08 | ENV_INTERRUPTED必须有外部见证；恢复成功后的正常N不能补跑；缺证据、H、资源异常、鉴权错误不能冒充ENV_INTERRUPTED |
| RT09 | 全批2事件、每槽1重跑、1小时恢复准入窗及健康门槛均强制；第三事件、同槽第二重跑、失败探针、旧闭批和并发claim全部拒绝 |
| RT10 | 控制器崩溃后只恢复保全/审查；未知是否已launch的槽不能再launch；已消费attempt不回退；暂停/修复不能悄悄改其他槽成绩 |
| RT11 | 真实CLI产生超过旧200 MiB及100000事件的受控证据流后，原字节/行顺序可复核，无truncated；低空间/写入失败会停止并保全，不补造完整Trace |
| RT12 | 两平台干净安装显示实际恢复配置；隔离环境不继承宿主AXI变量；完整题面、文件/Git保护、复核前检查点（包括会触发复核的健康探针）、最终评分及清理链均通过 |

新增验收器须用相反实现校准：故意恢复50次截断、到期继续转发、把retry_exhausted标completed、缺一条Trace仍接受、把普通N改ENV、允许重复claim。必须由行为/账本断言拒绝，不能把导入失败当检出。

无法证明以上条件的题，冻结前按同类要求替换并记录原因；不得按预期得分选择。只有题目公开的执行预算说明可以统一改为新时间/次数规则，并独立保存业务契约哈希；业务义务、原态、允许修改范围或评分含义改变则按新材料重新资格。

完成准入时重新核算：4类各5、至少8个独立真实仓库、每仓最多3、至少10题用户脏改且4题生产脏改、至少8题普通异步/取消/并发/资源行为。新U01的来源、模块跨度、价值和类别必须满足[原蓝图](https://github.com/BozhengLong/axi/blob/ff34b57d9587f23207f0b50f6d0a5dfed936d4a2/docs/19-v1-release-task-blueprint.md)的难度要求；不强迫模型为凑模块数多改文件。

## 8. 评分故障、Trace与资源

外部故障恢复额度与评分修复额度独立。正式开始后仍只允许**一次、最多24小时的同契约评分修复**。暂停新增、保存原分数、绑定同一产物，重做全部受影响资格并统一重评所有受影响最终/检查点。修复不能改题意、产品、模型、阈值或替换产物，也不能触发新的模型执行。第二项独立测量错误、参考语义分歧、修复失败/超时或证据无法补回，按已有必要条件是否失败给出NO-GO或INCOMPLETE。

最多可能有73份最终视图、27份v1复核检查点（正式任务/C7为22、初始健康1、恢复健康最多2、重跑最多2），即保守100份；实际清单按是否产生检查点及是否评分登记，不能伪造缺失的检查点。修复估时使用实际所有受影响视图，而不是只估算一个成功产物。健康探针的评分/保护检查包含在其每条后续5分钟窗口内；恢复探针全流程还须落在该事件的1小时恢复准入窗口内。

完整证据指可观察范围：代理请求体/原始返回、SSE、原生会话、stdout/stderr、终端输入输出、授权、任务初态/检查点/最终文件、Git和元数据、评分、审查、尝试/暂停/恢复账本及校验清单。API未公开推理和工具已经截断的中间输出不在可恢复范围内。新旧attempt分别封存，不覆盖旧文件；证据单独私有保存，公开报告脱敏。

建议转发及IO证据以64 MiB目标分块流式写入，清单保存顺序、字节数、哈希及完整结束状态；一条记录可跨块，不得因分块丢字节。原生Trace按产品原样归档。适配器使用有界解析缓冲或增量读取，不把全部终端/原生日志常驻内存，也不为限制内存丢弃落盘原文。通过RT11确认超过旧200 MiB及100000事件后仍可逐字节复核。分块和增量索引替代旧证据累计截断阈值，不把它迁移成另一项隐式任务次数限制。

确认后才测实时磁盘。R2用新65条模拟、两个恢复链及长Trace场景测量实际分配字节和工作峰值。首次容量要求取`max(57 GiB, 1.5×本批预计保留证据与工作量 + 9 GiB保全余量)`；已经占用的依赖不重复算作未来可用空间。估算必须包含所有73次可能尝试的保留数据，不能沿用旧57 GiB就声称足够。

每槽前及运行中检查可用空间；低于9 GiB时关闭新转发、停止被测进程并保全，登记设施资源异常，不通过删除旧Trace或自动清理Time Machine继续。容量估计不是无限输出保证，低空间不能伪装成任务能力失败。只清理本批标签绑定的临时执行/评分资源；保留所有原始证据、镜像及只读依赖。
