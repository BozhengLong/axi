# Axi与Claude Code同题归因方案

2026-11-15。状态：D1–D5已获用户确认。与[新发布契约](15-v1-release-contract-v2.md)共用D1–D5。设计提交时仅交付方案；后续执行依据见文末用户确认。

2026-11-16执行收尾：研究已按D5关闭，结论为**A-INCOMPLETE**。实际2个探针、6个任务、213次生成请求；E09公开语义分歧影响P3-Axi唯一失败，不能以同契约测量修复改预期。P4及Q组未启动，不能恢复未用额度。详见[结果报告](verification/2026-11-16-v1-attribution-results.md)。以下保留已确认的原计划，不将收尾完成写成归因研究完成。

## 1. 要回答什么

本研究回答三个问题：

1. 相同E/D任务、模型档位和预算下，Axi与Claude Code分别交付什么？
2. 可观察的输入、工具反馈、验证选择或执行机制能解释哪些差异？哪些只能记为未知？
3. 给出同一份可执行失败复现后，两产品能否修复？缺少定位信息是否是一个可改变的瓶颈？

“归因研究完成”表示预定对照、可信判定、证据对齐及结论限制齐备。它不要求Axi赢，也不要求E/D全部成功，更不等于新发布契约已经通过。结论可以是“未能归因”，但不能用未经验证的解释填空。

## 2. 固定对象与公平性边界（D3）

| 项目 | 固定方案 |
|---|---|
| Axi | `0330626249c916bf81612299cd6b58955ad8b8d9`，`review=auto`；不用最近尚未证实更好的提示候选 |
| Claude Code | 既有冻结镜像中的`2.1.322`，使用原生工作流；不插入Axi专用复核提示 |
| 模型 | 两边均请求`claude-opus-5-5`、`medium`；核对每个实际生成请求与响应公开字段 |
| 工具 | Axi原生文件工具/bash；Claude的Bash、Read、Write、Edit、Glob、Grep。禁用额外agent、联网工具、插件与后台任务 |
| 会话 | 每次独立HOME、项目目录、会话和Git初态；不带旧消息、个人记忆或前次结果 |
| 权限 | 相同允许根目录、保护文件和副作用规则；读取按产品规则，写入/bash由宿主逐次核对实际调用后批准；不采用跳过权限模式 |
| 资源 | 固定Linux镜像，2 CPU、4 GiB、只读依赖、独立工具缓存；串行交错运行 |
| 任务预算 | 每次30分钟、最多50次实际生成请求；重试计入。Axi为40工作+10复核，Claude在同一总额内使用原生流程 |
| 评分 | 最终产物与Axi复核检查点共用15分钟绝对窗口，最后5秒用于回收；Claude不强行制造同名检查点 |

选择0330626的理由：它已具有文件工具、权限和有界复核；最近两轮通用提示没有证明完整交付率提高。该选择只确定诊断对象，不宣布0330626可发布。最近候选及旧封存用于说明假设，不填进本轮新样本。

源码从固定Git对象装入隔离镜像路径并逐文件校验。不能误把当前工作区的候选提示当成0330626，也不reset用户工作区。现有冻结镜像可作为材料，实际镜像ID、CLI和辅助程序必须重新核验；不使用会漂移的latest标签或顺便升级CLI。

这是产品整体比较。原生工具实现、系统提示、上下文组织和复核策略不同，都是产品的一部分。相同模型名称不能证明网关内部权重和路由完全不变；只报告能核验的字段。单次胜负不能证明某个工具或模型导致了结果。

Claude实际使用的计数、总结或重试请求也留证。生成请求不能因为是内部用途而免计预算；count_tokens单列。若出现非约定模型、档位或无法核对的隐藏调用，判比较条件不成立，不能悄悄放宽限制继续。

## 4. 定位援助对照：8次修复任务（D4）

所有P组结束后才开始Q组。仍使用同一冻结产品，不修改Axi提示或CLI配置。

### 4.1 固定一个单缺陷起点

准备期从已通过资格的E实现制作一份人工单缺陷变体，目标为“共享缓存的写失效被错误用于本函数去重登记”。其余实现保持；必须证明原构建、原测试/类型、非目标契约及等待调用探针通过，仅目标共享范围场景失败。不能用同时含多项缺陷的旧模型产物来混淆修复原因。

该修复题与P组的“实现新API”不同，结果单列。变体、正确对照、原始源哈希、目标条款与失败复现，在P组开始前就固定，不能看P组结果后挑一个有利起点。

### 4.2 唯一干预：是否提供可执行复现资料包

- U（无定位援助）：提供相同的有缺陷代码、完整公开契约、原测试及修复要求，不给具体失败位置或复现。
- A（有定位援助）：在U的基础上，只增加一份通过公开API触发目标问题的可执行复现及对应失败输出。不给修复代码、私有状态检查或“修改哪一行”的指导。

“援助”作为一个资料包因素解释，不把其中的描述、脚本和输出各自宣称为独立原因。除清单中这份资料包及其入口说明外，代码、要求、预算、权限、模型和评分都一致。输入差异必须能逐文件列出。

| 配对组 | 条件/次数 | 次序 |
|---|---|---|
| Q1 | U，第1次 | Axi → Claude |
| Q2 | A，第1次 | Claude → Axi |
| Q3 | A，第2次 | Axi → Claude |
| Q4 | U，第2次 | Claude → Axi |

每次都是新会话，不能让同一会话先看援助再执行U。Q材料中出现的参考式实现不影响已经结束的P组，也不进入将来的发布题库。

### 4.3 修复成功条件

目标复现消失；原构建/运行/类型及全部非目标契约仍通过；最终代码通过完整E检查和等待调用探针；保护要求满足；新增回归在修复后通过、在这份单缺陷原态上由目标行为断言失败；报告与实际执行一致。

原态在此处指带缺陷的Q起点，不是没有新API的上游版本。仅断言导出存在、仅导入成功或修改测试预期均不能计有效回归。有援助时可以将给定复现转为回归，但须标明来源，不计作agent自主发现。行为说明已准确时，不强制改README或类型来凑diff。

## 5. 归因证据与结论强度

每份记录按以下链条对齐：公开条款 → agent实际读到的材料 → 工具实际返回与截断/错误 → 改动 → 实际测试 → 最后修改后的复验 → 最终报告 → 独立判定。

分类包括：工具/协议不符、任务理解或作用范围错误、验证选择不足、修复实现错误、预算/主动结束、评测设施问题、不可观察或无法归因。允许一份失败有多个已证原因，不强制挑一个标签。

| 证据组合 | 允许结论 | 不允许结论 |
|---|---|---|
| 固定工具输入在Axi上可重复违反工具契约，可信对照通过；并能关联失败Trace | 确认该工具/反馈缺陷；记录其影响路径 | 所有任务失败都由此导致 |
| Claude通过而Axi失败，但没有机制复现 | 该样本有产品结果差异，提出可检验线索 | 文件工具差、模型差，或Claude总体更强 |
| 同一产品U为0/2、A为2/2，辅助后的修复机制符合预期 | 两次一致支持“定位援助对此修复题有效”，自主发现/定位可能是瓶颈 | Axi或模型普遍不会推理；已证明总体因果效应 |
| Axi的U为0/2、Claude的U为2/2，两者A均2/2，且输入/预算符合 | 支持Axi在本修复题的自主发现或验证策略存在相对差距 | 仅凭结果就断定是哪一段系统提示造成 |
| 两边P或Q都失败 | 该条件下有共同失败现象，检查共享限制和任务难度 | 已证明底层模型能力上限；两边失败所以可放行 |
| 结果混合，或工具信息不足 | 证据不足/未能归因，列下一项最小可检验假设 | 加样本直到得到想要的解释 |

工具/协议机制确认至少需要同输入确定性复现两次、合法正例与真实错误负例校准，以及实际Trace的因果位置。评分本身若有疑点，应先验证测量，不能用模型投票决定真值。工具已经正确标明截断而agent未继续读取，要与“工具返回错误内容”分开。

API返回的思考摘要只作过程资料，不能独立证明内在原因。相同助手完成审查不称独立盲审。2次重复用于检查方向是否一致，不能支持总体可靠率或显著性结论。

## 6. 前置资格与环境搭建

用户确认后才创建新的研究目录、授权时钟和独占资源锁。旧目录只读，旧未用额度不继承。产品、输入、任务判据、实际测量和评分身份分别保存。

1. **产品与环境**：核对0330626真实源码、Claude及Bun/Node/pnpm版本；固定镜像、独立工作卷/HOME、只读依赖和隔离缓存；断开公网、宿主服务、Docker socket和真实凭据访问。只有relay能使用网关凭据。新入口不得改动宿主Axi工作区或用户配置。
2. **判据**：把最近的157条序列、等待调用诊断和D实际资源测量在新命名空间固定。公开条款、输入、允许输出、H/N分类与时间边界分别登记；不改旧研究文件。
3. **正反校准**：E两种登记机制、D两套参考/原生once/按需计时器正例均通过；旧登记/共享范围/恢复写资格、接收者、Promise观察、真实资源泄漏、恒真回归及仅导入失败负例得到预声明结果。监督器终止仍是不可判定，不能改成普通失败。
4. **重复与回放**：原测试及全部完整合法正例各5次预声明重复。Q正确对照全过，Q单缺陷变体只失败于声明目标。回放最近4份最终和4份检查点，使用各自匹配的原始初态；只验证已知结论，不填新样本。
5. **CLI全链路**：E、D、Q-U、Q-A四种输入×两产品，共8次完整模拟。实际执行构建/原测试/类型与新增回归，再封存、重建、评分；核对同组输入差异、权限关联、预算和停止。模拟不调用真实模型、不计能力。
6. **失败恢复**：保留取消、信号、空报告、文件/总时限、缓存恢复、worker回收、陈旧分数和停止排空检查。所有命令受同一个剩余评分预算约束；不得复活旧的10秒测试文件限制。
7. **真实探针**：以上通过并commit/push、核对远端后，只执行Axi与Claude各一次2分钟/12请求健康探针。验证真实模型/档位、工具写读执行和完整可观察Trace，不计能力。

任何必须资格未通过都不准入真实任务。引用旧通过证据时，须说明该检查实际依赖的输入、产品、环境与测量文件均未改变；不能拿旧报告标题代替当前资格。不能为了复用而遗漏新入口/新输入/新测量的完整模拟。具体复用映射写入新资格清单并留哈希。

现有客户端在一次CLI内对已知暂时上游错误的有限重试保留，仍计50次/30分钟。本方案不设新的整对或单方CLI补跑。上游故障使样本不可判定时，保留缺失，研究可以报告不完整；不能单独增加一次新运行取得漂亮结果。

P1–P4、Q1–Q4按第3/4节顺序固定。健康探针顺序为Axi→Claude。普通代码失败、预算用尽或诚实的未完成不阻止另一产品或后续预定组运行；它们是本研究需要的数据。

## 8. 归因研究的完成条件与止损

### A-GO：证据充分，归因研究可收尾

须同时满足：

- 全部前置资格和两个真实探针通过。
- P/Q共16个预定任务槽均有新执行封存、完整可观察Trace和可信判定。正常交付、普通失败或任务预算用尽都可形成可信结果；“运行器结束”不能冒充“交付通过”。
- 八对比较的产品/输入/环境身份符合规则；Q输入差异仅为已声明援助包；没有中途产品修改、答案反馈、未记账生成请求或样本筛选。
- 每份结果有机器判定与绑定产物哈希的人工源码/回归/报告审查。每类结论写清“结果差异、机制已确认、干预线索、未能归因”中的哪一级。
- 形成一个明确后续建议：保留0330626、提出具体工具/流程修复、提出模型配置实验，或说明当前证据不足。给出依据及下一项可证伪预期，不自动改代码。

A-GO不要求16份交付成功，也不要求一定发现Axi独有原因。它不满足发布G0–G6，更不表示E/D失败被消除。

### A-INCOMPLETE：证据不足，不能完成预定归因

以下情况停止新增并报告缺口：鉴权/隔离/保护问题、未知协议、证据损坏、未达资格、时钟不足、缺失可信样本，或超过允许的评分修复范围。有扩大风险时立即中断在途；否则在原预算内安全完成封存。未启动、环境不可判定与普通失败分列。不能用历史样本、模拟、人工参考或缺失值填满16个槽。

若评分实现故障发生在真实任务后，停止新增，先封存安全完成的在途任务，再做同契约修复。需要复现、合法正例和真实错误负例、当前版本重新资格以及全研究所有可评分封存的统一重评。原分数保留，实际脚本新哈希明确记录。更改任务含义、场景、预期、通过阈值或时间判定不是测量修复。第二项独立不可信评分故障直接结束研究。

新发现的既有契约缺陷可按先声明、统一适用的补充诊断处理，原机判保留；新的产品要求不追溯扣分。归因也可据此继续得出失败原因，但不能借补充诊断给执行中的模型补答案。

## 9. 交付与用户确认后的边界

保留请求/响应事件、权限原始与实际输入、原生Axi日志、Claude stderr/debug、初态/检查点/最终文件、Git、各版评分与脚本、源码和依赖身份、所有失败/修复记录。认证头和真实密钥不进入Trace。原始记录私有保存，公开脱敏方法、最小复现和结论；不承诺取得API未返回的内部推理或恢复工具已经截断的内容。

报告至少提供：
