# 不设任务次数上限与有界故障恢复

2026-11-17。状态：D1/D2已由用户确认，先记录设计，再在独立开发分支实现与本地验证。此分支不是已通过发布验收的新候选。

## 决定、事实与范围

用户先提出“可以重新区分，我觉得我们能否不设置上限呢”，随后明确选择“取消任务次数上限，连续故障仍有等待上限（推荐）”。确认日期为2026-11-17，确认人为用户。

| 编号 | 已确认的产品决定 | 本次落实 |
|---|---|---|
| D1 | 取消整项任务的固定LLM请求次数上限 | 同时取消40次工作、10次复核、50次总请求及Agent外层默认50次循环限制。正常工作及一次复核均可继续调用模型，直到完成、用户取消或明确错误。 |
| D2 | 连续临时故障仍有等待上限 | 用独立的故障恢复时间窗口控制429、5xx及已有可重试传输错误。重试完整计数，但不消耗工作或复核配额。超限保存已有日志/文件，明确未完成。 |

事实：C2的`tests/review.test.ts`明确要求第40次请求失败后停止且不进入复核。这是旧设计规定，不是此次发现的未覆盖重试漏洞。新规则替代该产品决定，旧C2和已关闭评测结果保持。

## 技术落实

以下是助手为实现D1/D2选定的参数与方法，不冒充用户逐项指定的数值。

- 默认恢复窗口为10分钟，可用`AXI_RETRY_WINDOW_MS`设置正整数毫秒。窗口从一次逻辑模型调用的首次尝试开始，覆盖请求传输及退避等待；完整成功后下一次调用重新计时。它不包含其他已成功模型步骤、工具运行或用户确认等待，不是任务总时限。
- 单次请求仍最多5分钟，并取恢复窗口剩余时间的较小值。到截止不再发送或接受迟到响应。使用单调时钟计算剩余时间，取消信号优先。
- 默认不以重试次数提前截断。内部实验/测试可显式设置`maxRetries`，日常CLI不设置它。退避默认1、2、4秒指数增长，最高30秒；有效`Retry-After`优先，零值至少等待1毫秒以免忙循环。所需等待达到剩余窗口时，等待到截止后明确停止，不能提前违反服务端等待要求或越过截止。
- 认证错误、无效协议等原不可重试错误立即结束。重试保留相同请求快照，不追加失败/半截assistant响应，不重新执行已经完成的工具。Ctrl+C可中止请求和退避。
- 默认auto仍只进入一次收尾复核：有修改/获准bash后，模型正常交付初稿时进入。复核不再有10次限制，也不再靠工作次数强制触发；复核的正常结束即为本轮结束。off不插入复核。
- 保留原始HTTP尝试、成功响应、重试及工作/复核计数。既有日志`budget`字段保留计数字段，新增明确的不限次数标记、`remaining=null`；日志版本升为4，避免旧读取器误当旧40/10配额。记录恢复窗口、尝试序号、等待和超限原因，不记录认证头。
- 恢复超限使用独立终态`retry_exhausted`，显示未完成及已有修改说明。保存现场指保留文件、追加式历史和Trace；不新增退出后恢复会话、持久shell或自动上下文压缩。

取消次数上限不等于可以无限持有资源：单次API/工具超时、文件大小/扫描界限、权限、日志故障停止和取消清理保持。不新增隐藏的任务总时间、Token或金额上限代替40次。上下文不足仍按真实错误报告；没有实现v2长会话能力。

## 本地验证与完成条件

先使用本地模拟API和临时文件，无真实模型消费。需要证明：

1. auto工作超过40次、复核超过10次、总计超过50次仍能正常完成；off超过50次仍能完成；只复核一次，工具结果配对完整。
2. 第40次429和跨越原50次边界的重试可恢复，已完成副作用不重复；成功调用后故障窗口独立重置。
3. 持续429/5xx/传输错误按时间停止；长Retry-After、请求超时、迟到成功及退避结束边界均不越过截止；没有真实睡满10分钟的测试，使用可控时钟并补真实短窗口/CLI验证。
4. 请求/退避中取消立即停止，后续用户任务可继续；认证/协议错误不盲目重试；窗口超限不得标completed。
5. Trace版本、次数、时间窗口、原始失败与终态能关联；敏感信息脱敏、日志失败停止不回归。
6. 新分支typecheck和全套测试通过；实际CLI配本地API完成长任务、故障恢复、截止和取消场景。真实模型评测未执行要明确写出。

本次只交付开发实现与验证。正式评测在外部控制器设置独立且事先冻结的时间/资源上限，不能借产品内部次数限制代替；新候选冻结、题包、有效样本及外部故障规则另写新方案后执行。不得续跑旧批、补旧分数或直接宣布达到v1发布门槛。保留本次模拟Trace，完成后commit/push并更新交接。
