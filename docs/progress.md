## 关于用户（协作须知）

- 职业是产品经理，不写代码。**代码全部由 Claude 写**；用户负责产品决策、做实验、dogfood。
- 用中文交流，喜欢简洁、务实的建议：先给对比表，再明确说"我推荐 X，理由是……"。
- 用户**明确邀请 Claude 提出质疑**。看到不合理的地方要直说，不要默默照做。
- 用户不懂编程语言之间的取舍，这类技术选型由 Claude 直接决定，并给出一句理由。
- API 用的是公司 key，额度很高，**不用考虑费用**，不要为了省钱降级模型。
- 2026-11-10：用户希望由助手承担自动试用和独立验收，先做 Axi / Claude Code 同题对照。用户手动试用为可选项。先写评测设计，确认后再搭建和执行。
- 2026-11-11：用户明确要求将此前成果 commit 并 push，并授权助手自行判断分支策略。阶段收尾应核对提交和远端状态，不能用本地文档或 Trace 归档代替 Git 提交。

## 已定的决策（2026-10-12）

- 项目名 Axi；技术栈 Bun + TypeScript（选 TS 是因为用户之前的项目都是 TS，而且 opencode 开源可以对照）。
- "从零"指：不用官方 SDK，不用 agent 框架，HTTP 和 SSE 手写。
- 先只接 Claude，模型 `claude-opus-5-5`。
- 目标是学习和实用兼顾，约束是"每个阶段都必须能跑，并且真的拿来用"。
- 每个阶段都先写设计文档，用户拍板后再实现。
- DOC-001：重要决策和产出写入开发日报。记录依据、产出链接、验证结果和后续事项。
- DOC-002：正式记录和 commit 说明使用中文，采用 STE 的清晰表达原则。目标是约 80% 接近，不要求完全符合英文标准。
- REPO-001：在 GitHub 建立公共仓库，发布当前项目。
- v0/D1：采用连续对话。每轮结束后等待输入，并沿用本次运行中的历史。退出后恢复会话放到 v2。
- v0/D2：默认显示 API 返回的思考摘要。使用灰色文字和明确标签，与正文区分。等待期间没有摘要内容时，显示“正在处理”。
- v0/D3：每次 bash 调用前展示工作目录和完整命令。输入 `y` 才执行；输入 `n` 或直接回车则拒绝。一次确认只授权当前调用。
- v0/D4：默认使用 `medium`，保留 `/effort medium` 和 `/effort high`。切换从下一轮用户任务生效，同一轮任务保持档位一致。
- v0/D5：拒绝命令后可以附理由，回车跳过。工具结果说明命令未执行，并携带可选理由。

上述新增决定的确认依据见 [2026-10-12 开发日报](devlog/2026-10-12.md)。
