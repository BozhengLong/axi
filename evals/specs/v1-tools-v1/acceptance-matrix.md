# v1 文件工具与权限验收矩阵

> 2026-11-12。状态：用户已确认规格，实施验证进行中。依据：[v1 设计 D1–D7](../../../docs/07-v1-design.md)。编号用于追踪要求，不表示已经有对应测试函数或已统计断言数；实际结果另写验证报告。

## 1. 原则

- 真实文件、文件模式和子进程使用临时目录验证；CLI 使用真实伪终端与本地模拟 HTTP，不调用真实模型。
- read/edit 的旧版本检查覆盖读取后、等待确认中、提交前的确定时点；使用屏障控制，不以随机时间差证明可靠性。
- 只承诺设计内的普通文件和并发边界。不用几个通过的竞态用例推导“无条件隔离所有外部写入”。
- 所有拒绝与错误场景都检查目标和旁观文件字节、模式、Git HEAD/索引及临时文件；不能只看报错字符串。
- 以下行为门槛均须通过。新任务的题面、参考实现与具体验收另在实现冻结后准备，本文件不是未见任务集合。

## 2. 文件与搜索

| ID | 场景 | 必须观察到的结果 |
|---|---|---|
| F-01 | read 分页、中文、emoji、LF/CRLF、BOM、无末尾换行 | 原文与行号分离；码点不损坏；版本对应完整文件；分页范围准确 |
| F-02 | 文件过大、增长、非法 UTF-8、NUL、单行过长 | 明确拒绝或不完整，不把乱码/半行当完整文本；内存与输出有界 |
| F-03 | glob 的子目录、隐藏普通文件和模式 | 在公开范围内正确匹配，结果排序；默认排除与根目录明确 |
| F-04 | grep 字面量含正则符号、大小写、零匹配 | 不偷偷按正则解释；返回准确路径/行号；零匹配为正常结果 |
| F-05 | 文件数、累计字节、时间、结果数到限；权限不足 | 返回 incomplete、跳过原因和实际范围；不声称完整搜索 |
| F-06 | edit 唯一匹配，包含用户原有未提交修改 | 只改目标片段；其余字节、普通模式/执行位、用户修改与 Git 索引保持 |
| F-07 | 零匹配、多匹配（含重叠）、空 old_text、非法参数 | 不写文件，不进行模糊替换或偷偷 replaceAll；给明确错误 |
| F-08 | 版本缺失、伪造、错路径、跨会话、淘汰或过期 | 拒绝，要求重新 read；grep/glob 结果不能充当编辑版本 |
| F-09 | 创建新文件；已有目标；父目录不存在 | 新建内容完整、权限符合约定；目标存在不覆盖；不隐式建目录 |
| F-10 | 同一 assistant 消息连续修改同一文件 | 按顺序执行；旧版本不能覆盖前一条的结果；每项有独立结果 |

## 3. 路径、授权与预览

| ID | 场景 | 必须观察到的结果 |
|---|---|---|
| P-01 | 相对/绝对内部路径、..、相同字符串前缀的相邻目录、NUL/URL | 内部合法路径可用；其余拒绝；所有文件工具一致 |
| P-02 | 根/父目录/目标 symlink、断链、FIFO、设备、多硬链接 | 不跟随、不阻塞读取、不修改；已观察到的身份变化使提案失效 |
| P-03 | .git/.axi、凭据名称、自有临时文件及 ASCII 大小写变体 | glob/grep 不吐出内容，read/edit/write 不绕过；strict 也不放行 |
| P-04 | 默认 project 读取与 strict 读取 | project 无确认但有自动决定事件；strict 逐次确认；操作结果相同 |
| P-05 | edit/write/bash 在两种模式执行 | 始终逐次确认；y 只对应当前提案；没有批量允许或隐式持久授权 |
| P-06 | 输入 n、回车、理由、yes/Y、多行粘贴、提前输入 y | 默认拒绝，理由回传，旧输入不能批准新调用；保留 R1 回归 |
| P-07 | 多改动块、超长差异、路径带换行/Tab、内容含终端控制符 | 所有实际差异都可见；超限不确认；路径保持单行；展示不能覆盖提示 |
| P-08 | 模型请求修改模式或把授权指令藏入文件/工具结果 | 不改变本地模式；只有用户在输入框的命令可切换；新会话恢复默认 |
| P-09 | 用户拒绝文件修改后模型改用 bash 提出同一效果 | 仍需授权；拒绝事实和理由进入历史；模拟拒绝后文件保持；真实模型遵守程度另审查 |

## 4. 冲突与提交

| ID | 场景 | 必须观察到的结果 |
|---|---|---|
| W-01 | read 后、提案前外部改了文件 | 旧 base_version 拒绝，外部新内容保持 |
| W-02 | 用户看差异期间外部改内容、替换目标或改权限 | 输入 y 后仍拒绝旧提案；不能重算内容后沿用该 y |
| W-03 | 新建预览期间另一程序创建目标 | write 发布失败；既有目标保持，不以普通 rename 覆盖 |
| W-04 | 临时写入失败、空间不足、权限不足、提交前失败 | 目标保持原态；清理只删除本调用拥有的临时文件；清理失败明确记录 |
| W-05 | 观察者读取正在编辑的文件 | 在支持的本地文件系统中只看到旧完整内容或新完整内容；不能用此证明无外部竞争覆盖 |
| W-06 | 模型工具参数与展示提案不一致；重复批准旧提案 | 不执行；输入、预览摘要、调用 ID 与提交内容一致 |
| W-07 | 提交已成功但后续日志或状态报告失败 | 不谎报未执行，不重复提交；停止本轮，保留实际完成状态或明确 unknown |

## 5. 中断与协议

| ID | 场景 | 必须观察到的结果 |
|---|---|---|
| I-01 | Ctrl+C 在输入、模型流、重试退避 | 停止，半截响应不入历史；下一轮可继续，原历史与签名不变 |
| I-02 | 取消 read/glob/grep | 不继续扫描；部分结果明确不完整；控制输入能及时处理 |
| I-03 | 预览/确认/临时准备时取消 | 目标不写，清理本调用临时文件；不执行队列后续项 |
| I-04 | 最终提交前后两个受控时点取消 | 提交前取消不生效；已进入提交按实际结果报告 applied/未应用，不按取消信号统一改写 |
| I-05 | 第一项写入成功，第二项确认时取消，第三项尚未开始 | 第一项保持成功且不撤销；第二/三项未写；每个 tool_use 均有结果 |
| I-06 | bash 派生同进程组子进程，取消/超时/正常退出 | 原有残留清理通过；子进程不能延迟写测试标记；主动脱离组不在此保证内 |
| I-07 | 取消后继续任务 | 没有自动额外模型请求；用户下一次输入才继续；工具结果配对正确 |
| I-08 | 超时、用户取消、普通 I/O 错误、未知提交状态 | 分类不同；未知状态不自动重放；保留可核对的实际输出 |

## 6. 留证与评测适配

| ID | 场景 | 必须观察到的结果 |
|---|---|---|
| E-01 | 自动读取、人工确认、拒绝、冲突、取消、成功提交 | 日志有调用关联、授权来源、前后版本、实际 modified 状态；不保存真实认证头 |
| E-02 | 提交前后分别制造日志不可写 | 提交前阻止写入；提交后保留实际状态并停止后续工作，不自动重做 |
| E-03 | 旧 CLI 与新 CLI 的模拟交付 | 适配器分别识别，未看到实际完整交付不算成功；新工具不被当作 bash 处理 |
| E-04 | 确认界面与 API 调用/文件预览不匹配 | 控制器停止，不盲输 y；不通过修改产品权限来放行 |
| E-05 | 两个版本及 Claude Code 的 Trace | 原生记录、终端、工具、权限、快照和验收收齐并校验；缺口不伪装完整 |

## 7. 校准和报告

实现后至少准备以下错误变体，分别确认相关场景会失败：

| 变体 | 对应检查 |
|---|---|
| edit 把唯一替换改成多处替换 | F-07 |
| 删除确认后的版本复查 | W-02 |
| write 在目标存在时直接覆盖 | F-09、W-03 |
| 路径约束只使用 startsWith(root) | P-01 |
| 取消后仍执行同批下一项 | I-03、I-05 |
| 已提交后按 aborted=true 报告未执行 | I-04、W-07 |

发布报告分别列出确定性门槛、C7 已知回归和新任务三方结果。记录所有启动、环境异常和未完成，不用重抽样清除普通失败。权限次数是界面决策点计数；控制器自动响应的时间不是人的等待时间。具体预算、一次整组三方环境补跑、绝对截止和成功门槛以设计 D7 为准。
