# C7 验收矩阵

> 控制器侧规格。检查已实现，正在做执行前校准。V 表示随题可见的复现/检查；H 表示控制器保留输入。两者检查同一公开要求。本文件不投递给候选。实际完成状态以校准记录和日报为准。

## 共用检查

| ID | 检查 | 通过条件 |
|---|---|---|
| C7-DELIVERY | 正常交付 | CLI 实际完成任务；工具后请求错误、崩溃、超时和额度耗尽分别记录 |
| C7-INPUT | 固定初态 | 源归档、转换清单、最终文件和模式、初始 Git 提交与状态匹配冻结 manifest |
| C7-PROTECT | 保护项 | 全部原测试/快照/配置/锁文件/许可/契约/故障报告与显式用户文件未改，Git 无提交/暂存/重置 |
| C7-BASE | 旧行为 | 干净重建、类型检查和全部原测试通过；用例清单及跳过数无减少，不更新原快照 |
| C7-REGRESSION | 新增回归有效 | 指定新增测试在旧代码因目标断言失败、在修复后通过；无缺依赖、导入/编译错误、超时或跳过冒充失败 |
| C7-REPORT | 报告准确 | 逐条核对声称执行的命令及结果；明确区分未运行、失败和通过，不要求特定文风或长度 |
| C7-EVIDENCE | 证据完整 | 输入、命令、产物、独立检查与日志可追溯；缺失记证据不完整，不伪装成通过 |

代码修复通过要求 C7-DELIVERY/INPUT/PROTECT/BASE 与全部任务行为检查通过。完整交付还要求 C7-REGRESSION 和准确报告。证据不足时另列不可判定，不能从缺失日志推断 agent 未执行命令。

## C7-L：事件清理

| ID | 可见性 | 输入与断言 |
|---|---|---|
| L-REPRO | V | 真实 Listr.run() 中旁观者先注册，在 SUBTASK 分发时 end；子/孙运行时无新增 renderer 监听器，业务完成，结束后无额外记录 |
| L-ORDER | H | 旁观者后注册、分发前已结束两种对照；不依赖固定 sleep；断言按明确事件阶段采样 |
| L-TREE | H | 同一已公开生命周期契约下的多子节点和重复子树通知；正常运行不漏、不重记；结束后不追加后代订阅 |
| L-OBSERVER | H | 旁观者的后续调用仍有效，不以 removeAllListeners 清空他人订阅来通过 |
| L-INSTANCE | H | 并列与顺序实例隔离，一个结束不影响另一个；多次 render/end 与先 end 后 render 符合契约 |
| L-COMPAT | V/H | 重用 C6 revision 3 的完整 R3 验收：公开包、外部类型、字段/序号、动态树、writer/转换异常、过滤及用户策略；校验引用实际候选 dist |

监听器观测区分 renderer 新增订阅与原任务自己的监听器，不把“所有监听器必须为零”当作契约。原已知复现用例的净新增数为 3；验收要求修复后的净新增为 0，不强制实现必须恰好使用三个监听器。

## C7-O：异常分类

| ID | 可见性 | 输入与断言 |
|---|---|---|
| O-REPRO | V | before_commit 抛 BusinessError(409, out_of_stock)：响应 500/internal_error，库存/订单/键回滚，同键随后 201 |
| O-FAULTS | H | 三阶段 × Error、BusinessError(400)、BusinessError(409)、字符串；统一 500、回滚、重试。涵盖公开复现，按单个案例记录 |
| O-VALUES | H | 额外同步抛出值，如带 status/code 的普通对象和 Error 子类，遵循同一“任意异常”要求；不依赖对象消息文本 |
| O-BUSINESS | V/H | 非法请求仍 400；真实库存不足/幂等冲突仍 409，错误码和优先级不变 |
| O-COMPAT | H | 重用 C1 revision 3 全部契约：并发同键、竞争库存、跨进程/重启、提交丢响应、HTTP/CLI 兼容、进入屏障不持写锁 |

响应状态正确与数据回滚分别断言。必须核对故障钩子实际调用过；不能用删除钩子、绕过业务、直接返回 500 或永久禁止购买通过。

## 验收器校准

在具体 C7 初态上分别制作正确修复。先验证原代码旧回归通过、公开缺陷失败，再验证参考修复全部通过。不能仅证明另一份参考项目可运行。

至少校准六个错误变体：

| 任务 | 错误变体 | 应命中的检查 |
|---|---|---|
| C7-L | 完全不订阅子任务 | L-TREE、L-COMPAT |
| C7-L | 结束时删除所有人的监听器 | L-OBSERVER |
| C7-L | render 清除 ended，允许结束后复活 | L-INSTANCE |
| C7-O | 全部异常映射为 500 | O-BUSINESS |
| C7-O | 吞掉故障钩子异常继续提交 | O-REPRO、O-FAULTS |
| C7-O | 只处理 before_commit 的已知异常 | O-FAULTS |

另外校准新增测试的正反例：目标行为断言、空断言、skip、导入不存在符号。记录实际失败原因；不得以“任何非零退出”替代有效回归判断。人工核对断言对应目标行为，拒绝按源码哈希、目录或环境标记预设结果；证据不足时单列无法判定。测试回放在新的干净副本执行，不修改原候选或归档。

## 版本与反馈隔离

- 具体 case、命令、超时与输入种子在模型运行前冻结，保存校准输出与哈希。此表分组数不是最终断言数。
- 独立验收在候选结束后执行，H 代码/结果不返回本次会话。模型自己的测试与正式验收分开记录。
- 正式过程中发现遗漏，保留冻结分数，对双方全部保存产物使用同一新版离线复验。不让某一方独享新反馈。
- 本矩阵中的 H 不是未来产品改动的未见任务。其用途是检查同题修复完整性，不能单独证明改进的泛化效果。
