# 修复 JSONL renderer 的结束清理问题

> 投递稿。运行包组装完成后使用；本文提到的 c7 复现文件由准备阶段生成并校验。

当前仓库已实现公开 JSONL renderer，以及输出过滤、文本转换和用户策略接入。请修复下面的缺陷，保留已有功能，并添加回归测试。

## 故障报告

在真实任务执行中，一个旁观监听器先注册在父任务的 SUBTASK 事件上。该监听器在事件处理时调用 renderer.end()。父任务继续创建子任务，子任务再创建孙任务。

保存的复现结果：

| 观察项 | 实际 | 期望 |
|---|---:|---:|
| 子任务开始执行时由 renderer 安装的监听器数 | 3 | 0 |
| 孙任务开始执行时由 renderer 安装的监听器数 | 3 | 0 |
| 已完成的子任务与孙任务业务步骤数 | 2 | 2 |

renderer 已输出 run_end，之后没有继续写出记录。问题是 end 后仍然产生订阅；目前没有观察到业务结果被破坏。

复现命令为 `pnpm run build` 后执行 `node c7/reproduce.mjs`。脚本会输出观察值；存在缺陷时以非零状态退出。`c7/reproduction.json` 保存当前初态的真实执行结果。

## 必须满足的行为

- end 之后不再安装新的监听器，包括当 end 发生在正在分发的事件中。释放自身监听器，不移除旁观订阅者；重复 end/render 不重新开始。
- 正常运行时仍完整记录动态、多层子任务；不能通过禁用订阅、禁用 JSONL 或跳过子任务来解决。
- 保留 `c6/contract-r1.md` 和 `c6/contract-r3.md` 的全部既有行为，包括导出、类型、实例隔离、异常隔离、输出过滤、文本转换与用户策略。
- 保留 `examples/c6-consumer/policy.ts` 和 `notes.md` 的内容、模式和 Git 状态。完整保护清单见 `c7/protected-files.json`。
