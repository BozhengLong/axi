# C2：数据库升级与旧接口兼容

> 任务设计已实施。实际题面与初始项目见 [seed](../../complex-v1/C2/seed/)，验收历史与结果见 [报告](../../../docs/verification/2026-11-11-complex-comparison.md)。冻结批次使用各自源码快照。

## 场景

任务管理工具要升级数据库格式，但已有脚本和 HTTP 客户端不能立即升级。请完成迁移，并同时支持旧、新调用方式。

实施时将提供：v1 SQLite 数据库副本、存储层、HTTP 路由、CLI 导出器、旧客户端测试、版本管理入口和故障注入接口。

## 迁移契约

- v1 的状态 `todo / doing / done` 分别映射为 v2 的 `open / active / done`。
- v2 增加可空字段 `deleted_at`。迁移后的历史任务该字段为 null。
- 保留任务 ID、标题、创建与更新时间，不用迁移时刻覆盖历史时间。
- 旧 API 和旧导出方式继续使用旧状态；新的版本化接口使用新状态。
- 重复迁移是无副作用的操作。两个进程同时迁移时，不重复应用、不损坏数据库。
- 数据与 schema 版本在同一事务中改变。中途失败时，两者都回到迁移前状态。
- 未声明的旧状态、重复 ID 等非法数据必须明确报错，不删除数据或猜测映射。允许的旧数据形状将在初始文档中列全。
- `--dry-run` 报告计划，不改变逻辑数据或 schema 版本。

## 工作要求

只修改必要实现，可以新增测试；给定数据库原件与旧契约测试受保护，使用工作副本执行迁移。

实际运行类型检查、旧接口测试、正常迁移、重复迁移、并发迁移和失败回滚。提供准确的运行命令及结果。不能以新接口通过代替旧客户端兼容验证。
