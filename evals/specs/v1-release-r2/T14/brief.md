# T14：修复路径与祖先同时预约造成的抽取停滞

项目为node-tar，固定提交`eb92e178af52cd191d48eb70a846f61cc4dade1b`。类别为R2真实缺陷修复。来源：[issue 469](https://github.com/isaacs/node-tar/issues/469)。已复现：没有其他任务占用路径时，`PathReservations.reserve(['folder/child', 'folder'], callback)`也没有启动callback。

异步Unpack会为entry.path及linkpath预约路径。请修复这一调用链，保留普通并发与抽取行为。需要理解`src/path-reservations.ts`、`src/unpack.ts`及路径规范化；不要求为了文件数量扩大改动。

| 编号 | 必须满足的行为 |
|---|---|
| C1 | 同一任务的直接路径可以包含另一个直接路径的祖先。没有别的任务阻塞时，这个任务立即启动一次；自身的目录预约不能阻塞自身。 |
| C2 | 仍正确等待其他任务的冲突预约。先前任务释放后，当前任务及其后续等待者按已有冲突规则前进；不丢任务、不提前让冲突任务并行。 |
| C3 | 不冲突的兄弟路径仍能并行。不能用全局串行队列、禁用预约或提前释放占用来消除停滞。 |
| C4 | 释放只影响本任务的占用。重复调用同一释放函数不再次启动回调，不清理其他任务的占用。同步释放及回调内新提交预约也能正确完成。 |
| C5 | 路径规范化后再判断冲突。保留现有点路径、尾斜线、Unicode规范化和Windows串行分支的行为；同一任务的重复路径不能造成自身死锁或重复执行。 |
| C6 | 实际异步Unpack抽取中包含entry.path与祖先linkpath时能完成。同步抽取及普通文件、兄弟条目、旧路径保护、错误传播、构建和类型保持。不能只给直接类调用打补丁，而让Unpack继续停滞。 |

不要求改变释放后`check()`对已结束回调的内部记录方式，也不要求新增全局事务或垃圾回收接口。保留原有公开API与已有正常调度顺序。

请新增`eval-regression/release-*.mjs`回归。可使用构建后的模块和公开抽取API。行为回归须通过明确的启动/完成事件和计数证明缺陷；不能把监督器杀进程或悬空Promise取消当作有效回归。

验证命令：`npm test`，以及`node --test eval-regression/*.mjs`。`npm test`包含原构建、类型和测试。Node22.23.5/Bun1.3.14/npm11.19.1已固定，依赖已安装；禁止联网与升级。README需说明修复涉及的预约边界，并提供本地可运行示例`examples/release-parent-reservation.mjs`，实际执行它。
