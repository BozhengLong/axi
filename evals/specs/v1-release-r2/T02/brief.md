# T02：修复共享导入配置的相互污染

## 项目与任务

项目为cosmiconfig，固定上游提交`07542d9b8912ca859bc554096021111e868fd323`。本任务属于R2真实缺陷修复。问题来源：[上游issue 372](https://github.com/cosmiconfig/cosmiconfig/issues/372)。本地已复现：两个配置导入同一个CJS模块后，先前结果和Node模块缓存中的基础配置都出现了另一个配置的值。

请修复导入配置的合并。理解`src/loaders.ts`、`src/Explorer.ts`、`src/ExplorerSync.ts`与`src/merge.ts`之间的调用关系。可以只修改必要文件，不要求为了数量制造改动。

## 必须满足的行为

| 编号 | 条款 |
|---|---|
| C1 | 含`$import`的配置合并不得修改loader返回的普通对象或数组，包括嵌套对象、嵌套数组和数组内的普通对象。一个配置的合并不得改变另一个已返回的合并结果。 |
| C2 | 结果中的普通对象/数组属于该次合并；修改这个结果不得修改导入来源的普通对象/数组。异步JS模块缓存，以及同步/异步自定义loader复用对象，均须满足。冻结的普通对象/数组来源也能合法合并。 |
| C3 | 保留现有优先级：依次合并导入列表，然后合并当前文件；后来的标量覆盖先前标量，普通对象递归合并。默认数组按来源顺序连接；`mergeImportArrays:false`使用后来的数组。数组元素本身不能被展开或丢弃。 |
| C4 | 同一来源重复导入仍按导入列表出现次数参与合并。链式导入、两个分支导入同一基础配置、同一explorer的不同load，以及不同explorer均不得互相污染。`cache:false`也不能依赖Node自动清空模块缓存。 |
| C5 | 不改变无`$import`时的加载/缓存接口。函数等非容器叶值保留值与身份。保留现有`__proto__`/`constructor`合并保护；不能污染对象原型。此任务覆盖无环的普通对象与数组，不新增循环对象或任意特殊实例的深复制保证。 |
| C6 | 保留同步/异步公开接口、路径和结果形状、转换器调用、缺文件/自导入/循环导入的错误行为，以及原有构建、类型和测试。不得通过关闭所有缓存、修改全局require缓存策略、序列化成JSON或吞掉错误来规避问题。 |

这里的普通对象指由对象字面量创建或原型为null的对象。本题的配置容器使用可枚举自有数据属性，不包含访问器或Proxy。返回结果不要求保留同一输入内部的共享引用拓扑；必须满足C1/C2的隔离和值语义。没有要求改变非导入加载结果的可变性，也没有要求复制函数。
